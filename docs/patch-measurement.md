## 记录什么

用户明确选择一个UTF-8差异文件，程序使用固定jsdiff 9.0.0解析Git普通统一差异和带文件头的GNU统一差异。保存新增/删除行、增删条目、净行数变化、上下文行、修改块、连续改动段、空白行，以及按可计量文本文件的数量分布。每个文件先得到数值，再计算全体文件的第7型分位数；二进制及其他内容无法计量的文件从这些文本分布中排除，保留未知数量。已知没有文本变化的空文件创建、重命名或权限变更保留已知零。

对象ID显示内容改变却没有修改块、相似度低于100%但未提供内容、或新增/删除缺少空文件依据时，内容计量保持未知，不能把这些元数据段当作零改动。空文件依据仅与固定空blob的SHA-1/SHA-256摘要及至少7位前缀比较，不读取目标文件，不输出提交号或用户内容哈希。没有相关证据的完整性仍来自所选补丁范围声明，不认证真实版本。

新增、删除、重命名、复制、内容修改、仅元数据是互斥文件类别；权限变化、符号链接/子模块模式另列，可以重叠。类型和模式来自差异结构，不执行目标文件。新增和删除相加是文本条目：替换一行通常算两条；它不是独立语义修改数，也不是完成目标数量。文件移动是否作为重命名取决于原始差异的检测设置，不能据此推断模型返工或代码作者。

修改块按输入中的@@边界计数；连续改动段是一个修改块内连续的新增/删除行，中间遇到上下文即分开。上下文行数、差异算法、空白忽略与重命名检测均保留用户声明，未知不猜。比较不同任务的这些数值前应核对生成条件；不能把修改块数量直接当作工作量、任务难度、修复质量或验收结果。

## 改动分散程度与声明

令已知文本增删条目为C，第j个可计量文本文件的增删条目为c_j。当C>0时，记录最大占比max(c_j/C)、占比平方和Σ(c_j/C)²及其倒数；C=0时三项均不适用。两个文件各占一半时，平方和0.5、倒数2。这只描述已知文本改动集中在哪些文件，不采用经济或行业阈值，不解释成难度、耦合、工作价值、缺陷概率或两个任务。存在二进制文件时不是全部改动的分散程度。

对每个连续改动段，比较删除文本和新增文本移除ASCII空格、制表、回车与换行后的结果，保存相同的段数。它不能认证“只是格式化”：字符串中的空格和缩进可能影响行为。文件用途（实现、测试、文档、配置、数据、其他、未知）、生成代码、仅格式化均来自本地清单的明确声明，程序不按文件名猜、不调用模型、不扣除声明的工作量。三组分类分别划分同一批文件，不能跨表相加。

## 清单与命令

```json
{
  "version": "patch-measurement-manifest-1",
  "requirementRevision": "45eb20b3-1876-4d23-af26-98a4e365bbba",
  "stage": "after_execution",
  "scope": "complete",
  "patchFile": "selected.diff",
  "generation": {
    "contextLines": 3,
    "algorithm": "myers",
    "whitespaceIgnored": "none",
    "renameDetection": "enabled"
  },
  "classifications": [
    { "path": "src/selected.ts", "role": "implementation", "generated": "no", "formattingOnly": "unknown" }
  ]
}
```

路径清单只留本地。patchFile相对清单目录解析，程序只读取这两个主动选择的文件；不会打开补丁内的任何路径、应用补丁、扫描仓库或执行Git/项目配置。classifications可以为空，未声明文件保留unknown；声明的path与解析后的目标路径精确匹配，删除文件用原路径。Git的a/、b/前缀由解析格式去掉；不自动识别大小写、路径别名或内容相似度。重复或未能关联的声明不静默忽略。

stage可为proposed、during_execution、after_execution、unknown。补丁可描述提案，并不能证明已应用或执行前的真实代码；要求修订和范围都是用户声明。没有原文件、版本验证或执行记录时，不据此增加“已完成”任务数。

```powershell
# 默认关闭，不读取清单、补丁，也不加载解析器
npm run contribute -- measure-patch --out .local/patch-disabled.json

# 用户主动选择后解析；旧输出不覆盖
npm run contribute -- measure-patch --manifest selected-patch.json --out .local/patch-report-001.json --enabled

npm run contribute -- schema --format patch-manifest --out .local/patch-manifest-schema.json
npm run contribute -- schema --format patch-report --out .local/patch-report-schema.json
```

生成的patch-measurement-1数值报告可在网页和应用共用的“本地代码结构”面板导入。原始补丁和清单包含代码及路径，不能导入报告入口或上传。补丁报告不是执行前/后的代码快照，compare-code-reports不对其作快照差值。

## 完整输入、资源与脱敏

固定解析器会宽容地跳过一些外围文字；本程序先检查整份输入的格式、行数、修改块计数和容量，再与解析结果核对。缺文件头、重复文件段、修改块重叠或行数矛盾、未知外围文字均不采用结果前缀。支持普通文本修改、创建/删除、空文件、重命名/复制、权限变化、带Git文件头的二进制变化标记及常见引用路径；二进制内容未知，报告明确partial。

当前不支持合并提交的combined diff、Git二进制数据块、邮件/富文本包装、SVN属性差异或只含@@的无文件头片段；遇到这些形式整份标为unavailable，不能截掉后称完整。输入为空的所选差异可记录已知零文件，但不证明没有其他工作。CRLF差异记录按行规范化，Unicode正文仍按UTF-8处理。

最大输入4 MiB、清单64 KiB、100000行、单行256 KiB、64文件、4096修改块及100000增删条目。解析在用户主动运行的本地命令中进行，没有后台监听、额外轮询或模型调用；这些是输入与工作边界，不是进程RSS或运行时间硬上限。正文只在内存中解析，不写临时源码、不执行补丁内容。

输出只有固定枚举、计数、分布、版本、测量时间和本地随机要求修订UUID；没有源码、文件/目录/函数名、提交号、源码哈希、原错误片段或自定义备注。Schema的一致性检查、包摘要与用户声明都不能认证任务真实发生，也不能防止本地用户伪造一份数学上自洽的报告；不升级为可信完成量或公共排名证据。

## 来源与许可

采用[Git官方差异格式](https://git-scm.com/docs/diff-format)区分普通补丁、文件操作与合并差异。解析使用[固定jsdiff 9.0.0源码](https://github.com/kpdecker/jsdiff/tree/v9.0.0)；只调用parsePatch，未调用applyPatch，也不执行所选代码。项目方法是在这些结构上进行计数，不声称这些资料验证过通用任务难度或生产率算法。

依赖精确固定为diff@9.0.0，npm锁文件保留分发包SHA-512；`third_party/jsdiff-9.0.0/SOURCE.json`记录来源、许可和实际解析模块摘要，保留未修改的BSD-3-Clause许可。运行时不自动安装或联网；安装工具包依赖是独立的首次配置步骤。摘要用于版本一致性，不是用户工作真实性证明。验证结果与当前构建状态见status.md。
