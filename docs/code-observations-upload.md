# 可选代码数值上传与本人反馈

更新：2026-10-15。对应D的数据摘要扩展、M的测量接入及F/U的本人反馈。新增字段默认不存在；没有开启采集、自动执行、自动上传或生产难度评分。

## 从本地报告到上传字段

先由用户选择范围，用measure-code-set、measure-python-set或measure-patch生成数值报告。程序读取用户指定的报告JSON，按根目标和同一要求修订关联；不读取源码、原始补丁、Git历史或其他目录，不调用模型。代码与补丁的原计量方法、版本和缺项规则沿用各自方法文档。

新增的上传位置是 `tasks[].observations.codeMeasurements`，版本 `code-measurement-observations-1`。旧Task、Envelope、历史反馈及默认模板不补写该字段；空数组不能冒充测得零，未提供时整个字段省略。

| 内容 | 保留的信息 | 不进入新上传字段的信息 |
|---|---|---|
| 代码快照 | 语言、原格式与算法版本、解析器/Python版本、声明阶段、状态、范围、重复/未测文件及原因、已有结构数量与分布 | 本地要求修订UUID、精确测量时间、输入物理字节与读取预算、重复的固定规则/限制字典 |
| Python结构 | 具名函数、参数、嵌套、语法与行数等已有数值 | 文件/类/函数名、源文本、错误片段、源码哈希 |
| JS/TS结构 | 按语言的函数、类隐式执行、模块、语法决策、调用等既有数值，以及已解析文本字节 | 文件定位、逐文件列表和源码片段；读取字节与已解析文本字节不是同一个量 |
| 补丁 | 状态、阶段、格式、差异生成条件、文件操作、增删、分布、分散程度、声明及未测内容 | 原始差异、路径、提交号、上下文正文、用户内容哈希 |
| 来源与绑定 | 固定来源 `unverified_client_program_report`、用户声明的任务/要求关联、描述性用途 | 认证完成、模型能力结论、真实难度、代码质量或验收证明 |

现有Envelope中的根目标ID、账期、Token、价格/费用及整理摘要等既有字段仍按原协议保留。这里去掉的是代码报告中的额外本地标识和时间，不能把这理解成整份上传没有任何UUID或日期。只保留数值和枚举也不等于没有再识别风险；这些新增数值仅用于本人的描述性分析，不进入公共事实、榜单或社区推荐。

## 本地绑定与编译

把根目标ID取自所选capture文件的envelope.tasks；本地requirementRevision取自测量清单。已有结算要求引用时，必须与对应requirementRef一致。没有结算引用时，程序检查报告与用户所选修订一致，仍不能认证这份修订确实属于该任务。

测得或部分测得的报告必须具有同一要求修订，不通过事后填UUID替代。单文件Python报告若没有修订关联，先使用带修订的测量清单重新测量；未测得且缺少修订的报告可以由用户声明绑定，但保持原未知阶段和空指标。一个本地要求修订不能绑定两个根目标；原始报告、旧代码和全部历史留在本地，不被覆盖。

```json
{
  "version": "code-observation-attachment-manifest-1",
  "tasks": [
    {
      "taskId": "41a86078-0cb5-46f4-9710-ef10dd21d5c3",
      "requirementRevision": "e243c020-eecb-4623-b919-a0b18dc9adf1",
      "reports": ["before-js.json", "after-js.json", "selected-patch-report.json"]
    }
  ]
}
```

这些UUID只展示格式，实际值必须来自本次根目标和测量清单。报告路径相对本地绑定清单解析；补丁必须是数值报告，不能提供selected.diff原文。

```powershell
# 默认关闭，不读取任何来源；输出不是可提交的采集清单
npm run contribute -- attach-code-measurements --out .local/code-attachment-disabled.json

# 显式选择报告后另存本地采集清单
npm run contribute -- attach-code-measurements --input local-capture.json --manifest selected-reports.json --enabled --out local-capture-with-code.json

# 由程序生成白名单上传字段，再预览分享范围与摘要
npm run contribute -- capture --input local-capture-with-code.json --out record-with-code.json
npm run contribute -- prepare --input record-with-code.json --share private --out preview-with-code.json

# 机器协议（结构校验仍需配套程序执行业务关系检查）
npm run contribute -- schema --format code-attachment-manifest --out code-attachment-schema.json
npm run contribute -- schema --format code-observations --out code-observations-schema.json
```

attach步骤只附加本地原报告和绑定；capture统一生成上传字段，并把本地代码事实纳入已有加盐整理摘要。所有目标先检查再一起采用，冲突或超过容量不输出成功前缀。相同投影可幂等重用，已有不同观察不采用最后写入覆盖。原要求变化、已上传记录修订及完整结算仍使用原有流程，不通过重新附加代码伪装新目标。

prepare会说明有多少根目标附加了多少份快照/补丁及多少缺项。提交继续使用已有预览、摘要确认或用户先前明确授予的自动上传权限；本功能不创建自动任务、读取历史或代替用户批准。只让模型依据已有程序报告操作流程，不能让模型凭对话或主观印象编造这些数值。

## 重复、范围与容量

一种测量族和阶段只选择一份快照；JS/TS合并报告和Python各算一种族。补丁每阶段一份。想扩大所选代码范围，应先由本地测量工具合并文件后重新生成同一份报告，不能把重叠的局部报告简单相加。

每目标最多8份快照及4份补丁，单次本地绑定最多100个目标、256份报告；每份原报告最多256 KiB，总读取预算4 MiB，路径清单64 KiB。整份上传最多256份代码报告，原HTTP 512 KiB和结构容量保持。超过上传体积时保留本地文件，缩小采集窗口或只为明确选择的部分目标附加代码数值，不能截断费用/代理、自动拆账或把未知覆盖说成完整。

在不同任务中出现同一文件并不增加唯一文件数量。同一阶段重复选择被拒绝；没有源文件指纹的情况下不能自动查明跨任务的代码重用，因此本人反馈不汇总成唯一代码量、完成量或生产率。

## 本人反馈算法

服务端使用纯程序计算 `code-observation-insights-1`。保留本次总根目标数、附加数、快照/补丁数、执行前/后涉及目标、提案涉及目标，以及部分/未测得数量。来源、阶段、绑定和范围均是客户端声明。

代码按语言、解析算法及版本、Python版本、阶段和覆盖分组；补丁还按差异格式、上下文、算法、空白忽略及重命名检测分组。各组列出测得/部分/未测得数量。每组的观测单位是“一项任务的摘要数值”，计算已知数、未知数、不适用数，以及最小值、中位数、P90、最大值和均值，使用第7型分位数。

代码scope的coverage描述所选范围，并非任务验收覆盖率：范围未知时仍可保留已选文件的已测数值，但只进入“范围未知”组，不解释成整个任务或项目的完整代码。code-measurement-observations-1定义为本人反馈用途，即使既有statistics同意为true也不发布这些新字段；后续用途扩展须另定版本与授权范围。

例如一项任务有三个圈复杂度为1的函数，另一项有一个为9的函数：两项任务各自P90为1和9，因此“任务P90摘要”的中位数是5、P90是8.2；合并四个函数后的P90为6.6。这些是不同对象，本反馈明确展示前者，不用任务分位数的均值或分布冒充函数总体分位数。

函数数为0时计数是已知零，函数圈复杂度等空分布不适用；未解析时这些值未知。补丁没有已知文本增删时分散程度不适用，二进制或内容缺失仍单列未知。部分范围只描述测得部分；前后阶段分开展示，没有用户范围确认及源版本核对就不计算配对变化。

最多计算64个条件组，超过时撤去整份附加分布并报告容量，不挑前64组当作全部。网页和应用共用同一个反馈组件，每页8组，换页只操作本地结果，不再请求服务器。CLI反馈给出整体覆盖和含义，完整字段保存在本人的反馈JSON中。

## 公共数据与历史

新字段不参与代码难度、任务验收、费用分配、共同工作条件、最低Harness选型或推荐算法，也不用于提高证据等级。公共事实编译器口径不变，公共接口继续读既有数值事实，不为这个字段扫描所有私人Envelope。本人数据读取继续使用原来的身份与权限规则。

旧反馈不回填、不重算；新字段缺失时原反馈结构不变。网页、后端及贡献工具包需要使用配套版本；尚未切换的旧服务不能接收新字段，不能因本地编译通过宣称已经上线。当前构建、测试与备份记录见status.md和optimization-progress.md。
