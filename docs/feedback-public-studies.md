# 私人反馈中的相关公开评价

协议：`feedback-public-study-1`。本功能为私人反馈中的模型推荐附加已经发布的来源留出评价，不改变推荐顺序、预计费用、节省比例或主榜算法。网页、桌面和文字导出使用同一套解释。

## 两份结果采用不同人群

私人推荐沿用原有参照：排除当前上传身份及已确认同源记录。公开评价使用整个公开社区的已知关联组，没有针对当前用户重新排除本人。因此，附加结果只能作为相关公开观察，不能称为本次私人推荐的独立验证。

报告明确保存 `population=whole_public_community`、`ownerExclusion=not_applied` 和 `relationship=context_only_not_recommendation_validation`。私人参照中的 `referenceSnapshot.excludesContributor` 不延伸到附加公开报告。

本功能不在请求内重算留出、不重新分组、不调用模型、不读取另一份全社区原始记录。它复用启动时已校验的公开报告和本次已有公开事实版本。

## 附加条件

首先按已存在的 `modelWorkCondition` 精确匹配任务条件，包括任务类型、工作规模、验收口径、证据范围、费用口径、月份等字段。再核对模型的供应商、型号和版本，以及下列完整运行配置：

- Harness 名称、版本、型号、运行环境；
- 套餐及套餐版本；
- 自主或辅助执行、工具范围、推理设置、缓存设置。

同名 Harness 的版本不同，或者模型版本、月份、费用范围不同，均不会套用报告。只从该模型在目标中冻结的配置取值，不在评价数据中重新挑最低费用配置。

多个目标包含同一任务条件时，按固定规则选择：特定任务类型优先，再按条件数较少优先，最后按目标标识排序。规则不读取费用、排名、报告是否已准备好或附加诊断结果。首选目标没有报告时显示缺项，不回退到另一份更有利的报告。

选中的报告必须匹配当前事实版本。目标的月份、范围、任务类型、完整条件集合与权重也要一致。数据已变化时不附加旧数值；已经冻结的私人反馈仍保存其当时的结果。

## 两个统计对象分别展示

`matchedCondition` 只保存与推荐精确匹配的一个条件：已结束根目标数、验收数、支出、关联组数、固定权重和单位验收费用。费用为该条件总支出除以验收数，验收为零时金额为 `null`，支出仍保留。

`targetResult` 保存该模型在完整固定组合上的结果。对条件 s，以固定权重 q、支出 C、已结束根目标数 N 和验收数 A 计算：

```
每根目标支出 = Σ(q_s × C_s/N_s)
验收比例     = Σ(q_s × A_s/N_s)
单位验收费用 = 每根目标支出 / 验收比例
```

观测组重采样和逐组删除来源影响属于完整组合，不属于上面的单条件。多个条件时两者数值可以不同。单条件公开单位费用也不直接乘以本人的目标数来替代原推荐算法。

后续可选 `targetResult.weightSensitivity` 保存该模型的任务构成情景摘录：固定同一报告的配置，在预定正权重情景中计算费用范围和模型对关系变化。它同样属于完整组合，不能解释为本次私人建议的验证或未来费用区间；旧反馈不补写。方法与预算见 [任务构成情景](ranking-weight-sensitivity.md)。

各诊断仅保留匹配模型及其公开方法元数据；不携带其他模型的分项、选择侧费用、私有来源标识、原始矩阵、逐次抽样或精确删除极值。来源影响沿用公开档位，不能倒退为私人精确数值。

零费用与零验收分别说明。重采样不展示范围、达到容量、支持不足、旧格式缺项、无界和未知均保留原因，不填零。观测组重采样中间 95% 范围不是已经校准的 95% 置信区间，不保证未来费用；来源影响档位也不作为模型排名。

## 版本、历史与容量

新生成的格式2公开报告可附 `sourceBalance`，私人反馈只保留当前模型的公开变化档位，不保留管理员报告的精确来源均衡费用。变化不超过5%时不细分方向，历史没有字段时不补算。此项仍是全社区背景，不代表本人排除或私人推荐验证。算法和披露边界见 [来源等权对照](ranking-source-balance.md)。

新贡献反馈的模型推荐可包含 `publicStudyEvidence`；套餐建议、日记与订阅分析不强行附加模型评价。字段可选，旧反馈按原有结构读取，不补写“未开展”或当前评价结果。缺字段的界面说明是“生成此反馈时未保存相关公开评价”。

第一次成功保存反馈时，将匹配结果、报告时间、目标标识和事实版本一同冻结。后续读取直接返回旧反馈；社区变化、报告换版和后续价格变化不会覆盖该历史。

状态包括：未配置目标、超过容量、无匹配目标、无报告、事实版本变化、报告与目标不一致、模型未入选、模型支持不完整，以及完整配置不匹配。这些状态只保存原因，不夹带不适用的数值。

索引最多处理 8192 个条件条目和 8 MiB 的计量索引内容。单项附加摘要最多 8 KiB，一份反馈全部附加摘要最多 256 KiB。超过整份预算时全部附加摘要统一标为容量不足，不只保留前几个推荐。容量不改变原推荐或费用。这些是应用逻辑预算，不是进程总内存硬上限。

共享界面使用折叠区，展开后可读匹配条件、完整组合、完整 Harness 配置和报告时间版本。界面和文字导出只格式化保存的结构，不发起查询、不重新算排名。桌面通过原有手动读取反馈入口获取，没有新计时器或后台轮询。

## 实现位置

| 文件                                                         | 责任                                   |
| ------------------------------------------------------------ | -------------------------------------- |
| `shared/feedback-public-studies.ts`                          | 结构校验、固定目标匹配、报告摘录和容量 |
| `shared/personal-feedback.ts`                                | 在原模型推荐上保存可选摘录             |

| `shared/feedback-public-studies-text.ts`                     | 网页、桌面和文字导出的共用解释         |
| `shared/FeedbackPublicStudy.tsx`、`shared/FeedbackPanel.tsx` | 共用界面                               |

这项接线不等于前瞻时间评价。未来任务的登记、时间边界、持续观测和截止事实快照另见 [前瞻时间评价待实施方案](ranking-time-evaluation-design.md)。生产难度分级、自动采集、生成、上传和登录启动仍默认关闭，提醒时间仍为可修改的 17:30。
