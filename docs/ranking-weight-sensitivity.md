# 任务构成情景分析

方法版本：`task-weight-sensitivity-1`，2026-10-15。对应清单 S-07 的任务权重部分。输入为已经校验、已经公开的来源留出报告；模型、版本、每个条件的完整 Harness 配置、验收与费用事实均固定。

这项分析回答：如果工作类型和细分条件的比例变了，原有观察数据算出的费用会怎样变化？原榜单名次和原选择模型不改写，结果不是重新选出来的推荐或未来预测。

## 情景与计算

设完整目标有 K 个条件，原权重为 q，条件支出、已结束根目标数和验收数分别为 C、N、A。所有模型使用相同情景：

1. 原固定权重。
2. 所有条件等权。
3. 每次只将一个条件的原权重乘 0.5，再统一归一化。
4. 每次只将一个条件的原权重乘 2，再统一归一化。

K>1 时保留 `2+2K` 个预定配方；K=1 时仅保留原基准。不同配方可能得到相同权重向量，配方数不是独立样本数，更不是胜率的分母。极值同值时只列出固定顺序的第一个配方，不称其唯一。

倍率作用于相对权重。例如原份额 1/2 的条件乘2之后，最终份额为2/3，不是100%。条件等权与“任务类型等权、类型内条件等权”含义不同：细分条件更多的类型会获得更多总权重。这里不把条件等权称为更加公平、真实或用户需求。

每个情景计算：

```
R(q) = Σ(q_s × C_s / N_s) / Σ(q_s × A_s / N_s)
```

正权重归一化因子在分子分母中相消。程序对正项补偿求和，不使用删除失败条件、平均各条件 C/A 或先舍入货币再比较的方法。原基准为这份评价报告的原权重费用，不是选择集费用或当前全量榜费用。

每模型输出原基准、条件等权费用、全部已检查配方的最小/最大费用、对应配方、相对原基准的最大绝对变化及最大相对变化。极小正金额用“小于0.0001币种单位”表达，不舍入成确认零费用。

同时保存 `reportedBaselineCost`（原报告保存值）和 `baselineCost`（从公开分项补偿求和重算的基准）。原报告校验本来允许 `1e-10×max(1,费用)` 的数值误差；兼容检查沿用其原公式、原条件顺序和容差，不用下面的模型关系相对容差拒绝旧合法报告。两值不完全相同时明确说明，所有情景和变化量使用重算基准，原保存值不覆盖。已知下溢、非有限计算或数值不兼容标为整份附加 `numeric_unavailable`，不会阻断应用加载原报告，也不保留算到一半的模型结果；意外程序错误继续抛出。

## 模型关系

只对具有完整且有限单位验收费用的模型逐对比较。每对模型使用同一个配方；不能用 A 的最低情景和 B 的最高情景来断言谁更便宜。

若原基准能分出高低，至少一个情景中的方向严格相反，则记为一次关系反转。若原基准在计算容差内接近相等、情景中出现可分辨高低，则另记一次原接近相等关系分开。每个模型对最多计一次，不按出现反转的配方个数计“成功率”。费用范围重叠本身不算反转。

计算采用相对 `1e-10` 容差，没有固定的绝对金额下限，不会把任意小的正金额直接当零。容差用于浮点比较，不是商业等价区间、严格数学并列或统计显著性。两个范围是否重叠也不提供统计推断。

公开报告中未完整支持的模型保留缺项，不读取被隐藏的内部条件，也不在剩余条件上重分权重来使其重新合格。结果显示参与比较的有限模型数量；未参与不等于与其他模型相同。

## 零值与性质

本方法的全部情景权重严格为正，因此同一完整数据是否存在正验收、是否全部费用为零不会因为这些权重变化而改变：

| 数据               | 处理                                               |
| ------------------ | -------------------------------------------------- |
| 至少一个条件有验收 | 总体分母为正，其他零验收条件及其费用保留           |
| 全零验收且有支出   | 没有有限单位费用，保留该状态，不参加有限模型对比较 |
| 全零验收且全零支出 | 0/0未定义，不称免费完成                            |
| 有验收且全零支出   | 全部情景费用为零，绝对变化零，相对变化不适用       |
| 原模型缺项         | 整个模型未计算，不能因权重变小而补齐               |

正数累加发生下溢或费用计算非有限时明确报错，不转成自然零费用或零验收。所有费用同比缩放时，绝对费用同比变化，关系和相对变化保持一致；N、A、C同比复制时，单位费用保持一致。

## 不能推出的结论

这不是整个联合权重范围的最优化，也没有覆盖所有可能的任务组合。例如四条件等权、验收率均为1时，A各条件费用为 `[11,11,25,25]`，B为 `[20,20,20,20]`：

- 原基准A=18、B=20；逐项采用0.5或2倍率都没有反转。
- 同时将两个高费用条件乘2，A=`122/6≈20.333`，超过B。
- 同时再将两个低费用条件乘0.5，A=`111/5=22.2`，同样超过B。

因此界面只说“这些逐条件配方中未出现反转”，不称在所有0.5至2倍联合变化下都保持顺序。方法边界例子不进入公共真实统计。

分析只改变已经公开的数据权重，不重新抽样、不重新选择模型或 Harness，不评估来源是否独立或事实是否真实。这里的范围不是置信区间、未来费用上下界或对模型能力的评级。来源平衡权重、重新选型稳定性和前瞻时间评价分别继续推进。

## 接线、历史与资源

服务启动加载并校验公开评价目录后计算一次，保存在该实例的有限映射中。请求只取已有结果；不创建后台任务、不读取数据库正文、不访问账号或模型，也不按每个访问者重算。多个页面与私人反馈共用同一份计算。

结果放在 `RankingStudyView.weightSensitivity`，保存原报告、目标和事实版本标识。原公开报告文件、ID和摘要均不变。基础排名规则 `boards-13` 与事实版本计算保持原样，新方法版本单独进入公开表示版本及 `policy.taskWeightSensitivity`，不会仅因附加情景而要求重做历史来源留出。

只有报告仍匹配当前目标和事实版本时才展示。新私人反馈可保存单模型摘录；旧冻结反馈缺字段仍保持原样，界面说明当时未保存。私人推荐已排除本人，而其附加公开报告没有排除本人，原有适用边界不变。

每报告仍受128模型、256条件/模型和8192模型条件总量的公开协议限制。目录最多128份报告；预检整个目录的配方模型对比较最多400万次、情景条件处理加模型对比较最多2000万逻辑单位、情景数值最多50万项。目录预算超限时全部附加结果标容量不足，不保留先算出的前缀；原报告与主榜仍可用。逻辑预算不等于进程RSS或运行时间硬上限。

网页使用独立折叠区；私人反馈和文字导出使用同一解释。已结束但未验收的费用继续存在，进行中目标仍遵循原报告的纳入范围，没有因此被判为失败。默认采集、上传与难度分级设置不变。
