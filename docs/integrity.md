# 证据、核查与防造假

OpenCost 分别记录费用、工作、连续范围和额度证据。开源客户端、用户填写的表单及本地日志都能被修改；结构检查、哈希和客户端签名不能证明任务实际发生。默认榜单只接收符合独立核验要求的记录，自报观察与其分开。

## 1. 证据等级

| 维度     | 等级     | 可成立的陈述                                   |
| -------- | -------- | ---------------------------------------------- |
| 费用     | C0       | 用户申报金额，服务端已检查结构和算术           |
| 费用     | C1       | 用户附带本地采集器信息；服务端没有独立账单核对 |
| 费用     | C2       | 登记验证方核对本期实际费用及归属范围           |
| 工作     | W0       | 用户申报验收情况                               |
| 工作     | W2       | 独立环境按已登记条件核对工作成果与记录         |
| 连续范围 | declared | 用户声明记录完整                               |
| 连续范围 | verified | 验证方核对完整连续范围、所有结果及稳定账期标识 |
| 额度     | Q0       | 额度来自自报，尚无供应商侧独立核对             |
| 额度     | Q2       | 获授权的验证方核对额度窗口、消耗量与活动范围   |

C1 只说明提交了采集器元数据，不证明采集器运行过或金额真实。用户自己的截图、签名 JSON 或 CI 日志不能自动升级为独立核验。费用核验不自动证明成果验收，也不自动证明套餐额度。

发票可以证明一笔付款，不能单独证明任务分摊；模型调用日志可以证明调用，不能单独证明成果可用。核验方必须按检查项分别承担责任。模型、提供商与 Harness 的路由别名也须按真实可识别信息填写，不得把不可见的底层模型版本编造为已知版本。

## 2. 各环节的处理

| 环节         | 已执行检查                                                                                     | 仍由什么事实决定                                         |
| ------------ | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 接收         | 封闭字段、白名单、数值上限、512 KiB 正文上限、最多 500 项任务；拒绝原文和任意文件字段          | 客户端是否诚实填写，需要独立材料核对                     |
| 本地预览     | SDK 重新计算结构、费用和内容摘要；预览不联网                                                   | 用户查看的是本次完整待发送字段                           |
| 服务端预览   | 检查访问身份、保存同意、来源、账期和证明；生成 10 分钟令牌                                     | 令牌是内容确认凭据，不是账单真实证明                     |
| 提交         | 令牌绑定持有人、完整内容和证明；变化需重新预览；同源浏览器策略与 Bearer 身份                   | CLI 无 Origin 时允许访问，但仍必须持有凭据               |
| 去重         | 稳定本地账期、费用事实指纹、幂等键、签名 nonce 和验证方账期标识分别去重，事务内执行            | 自报者改写数值能绕过经济指纹，因此不能靠指纹获得可信等级 |
| 独立证据     | 登记 Ed25519 公钥、授权检查项、持有人、完整摘要、有效期、稳定来源、nonce                       | 核验方必须实际连接账单、记录和执行环境                   |
| 范围完整性   | 完整、连续、全部费用归属；有进行中任务或未分类任务的整期不进入公开比较                         | 是否隐瞒失败由核验方对连续账期、调用范围和任务清单核对   |
| 工作量与验收 | 领域、类型、工作单位、材料规模、验收计数一致；未知单独分组                                     | 预登记清单和原始计量记录留在用户本地或授权核验环境       |
| 公开分组     | 每组至少 20 项任务、5 个来源、单来源不超过 35%；各证据类别分开                                 | 来源不等于独立真人，门槛不等于统计显著性                 |
| 可选测量     | 人工时间、过程事件、返工、修改与各计时指标重新满足各自发布门槛                                 | 缺测值不补零；总榜需完整测量覆盖                         |
| 费用分摊     | 币种、退款、实付与等价金额分开；整数守恒；未知 Token 禁止按 Token 分摊                         | 选择的分摊方法仍是会计规则，不是任务独立付款事实         |
| 排名         | 同领域与证据，任务类型等权、类型内条件等权；每条件选最低验收成本 Harness；零验收和失败费用保留 | 固定事实分组无法消除材料差异与最低观察值的选择偏差       |
| 套餐额度     | Q2 独立核验、固定窗口、无重置、隔离活动、精确计量；相邻月份；价格快照一致                      | 观察比值改变不能直接归因于供应商缩减总额度               |
| 存储与访问   | SQLite 事务、凭据 HMAC、私有原始证明、认证的个人接口；请求日志不含正文                         | 部署后还需持久卷、备份恢复、运维访问与密钥管理           |

所有版本标记为 `demo` 或价格快照以 `synthetic-` 开头的内置示例，不能只把 origin 改成 real 后上传。服务端和存储层拒绝 synthetic，社区计算也默认排除 synthetic；只有明确的示例接口允许计算合成数据。删掉所有示例标记并编造新数值仍属于造假，必须由独立证据控制其是否进入已核验榜单。

费用事实指纹忽略随机任务 ID、任务排序、摘要字段和分享选项。完全相同但确实独立发生的费用记录也可能被拦截，冲突不等于作弊裁决。应由运营核对来源和实际账期，不能通过随意改金额绕过。

## 3. 公开与隐私

默认比较要求 C2、W2、verified；公开额度另要求 Q2。用户主动选择自报观察时，其他证据组合也必须分别成组，不能混成一个有“已核验”外观的排行榜。

公开信息不包含贡献编号、个人记录时间戳、来源哈希、账单编号或原文。工作摘要只由区间和枚举生成，且在同意公开摘要的记录中重新达到门槛。账户内部的个人记录可以完整展示给持有人。

每个分组至少 20 项任务、5 个来源、单一来源不超过 35%。可选测量也独立使用这一门槛。来源均衡成本和来源间范围用于观察集中影响；某来源没有任何验收成果时，不丢掉它计算更便宜的来源平均成本。

已核验来源按验证方稳定代号归并，自报来源只能按访问凭据归并。一个人可以创建多个访问凭据，持有多个供应商账户，也可能从多个验证方获得证明，因此这些规则不是独立真人身份系统。真实社区数量不足时应显示空榜，不用自报或示例补齐。

大量固定分组发布仍可能与外部信息组合推断参与情况。当前措施是区间化、门槛、来源集中度和固定查询；没有宣称达到差分隐私或不可重新识别。

## 4. 独立证明协议

验证方只读取用户明确授权的材料。原始账单、源码、文稿、媒体和内部系统数据不发送给 OpenCost 贡献接口。OpenCost 访问密钥也不能交给验证方；客户端先计算公开持有人代号。

```json
{
  "issuer": "independent-verifier",
  "subject": "SHA256(canonical(envelope))",
  "source": "验证方分配的64位十六进制稳定来源代号",
  "contributor": "SHA256(客户端访问密钥)",
  "coverageRef": "验证方分配的64位十六进制稳定账期代号",
  "nonce": "随机 UUID",
  "issuedAt": "2026-10-10T00:00:00Z",
  "expiresAt": "2026-10-11T00:00:00Z",
  "checks": { "cost": true, "work": true, "coverage": true, "quota": true },
  "signature": "64字节Ed25519签名的无填充base64url"
}
```

上面是字段说明，哈希和 UUID 须替换成实际值。签名内容是删除 signature 后的 `canonical(payload)` UTF-8 字节。规范化对对象键按字符编码顺序排序，保留数组顺序，不允许依赖系统语言的排序。签名有效期最长七天，签发时间不超过服务器时间一分钟；过期、越权检查、错误密钥或内容变化均被拒绝。

`contributor` 绑定发起提交的访问凭据，别人取得证明也不能用自己的密钥提交。`coverageRef` 在 checks.coverage=true 时必需；验证方必须对同一实际账期、同一来源稳定复用，不能每次随机生成。服务端对 issuer、source、coverageRef 的组合去重，因此重新签 nonce 或换内容也不能把同一个已核验周期计入两次。它不包含实际账单编号。

签名与 envelope、分享选择全部绑定。重新选择分享范围或修改任一字段，需要重新出具证明。nonce、核验账期索引、记录与请求幂等写入在同一事务中完成。签名原件保存在私有 attestations 表，供后续核查；它不进入公开接口。

`TRUSTED_ISSUERS_FILE` 指向服务端 JSON。每个 issuer 配置 SPKI PEM 格式的 Ed25519 publicKey 和允许的 checks，可为 cost、work、coverage、quota 的子集；还必须明确 status、allowedProviders、allowedDomains、allowedBilling、allowedModels、allowedHarnesses，以及可为空的 validFrom/validUntil/distrustSince。各列表只接受管理员配置，`["*"]` 表示明确授权全部；旧配置缺少范围时拒绝加载，不能静默扩大权限。Harness 范围包括所有后代参与的 Harness。贡献人不能自行登记公钥。持有 cost/work 权限的验证方不能签发 quota 权限。

status=active 可以接收新证明，retired 保留符合范围的历史但不接收新签发，revoked 取消历史公开可信资格。distrustSince 可限定不再信任的签发起点。新签发还要满足签名时间范围。正常换钥请使用新 issuer ID，旧公钥以 retired 保留；不要覆盖旧 ID 的公钥。修改配置后重新加载服务，随后公开读取重新应用当前授权；原签名、原入库等级和私有记录完整保留。上传签名过期不等于历史成绩到期，不能把七天提交有效期用作历史成绩期限。

验证方应逐项执行：

1. **cost**：核对付款、退款、币种、账期、全体调用与分摊，区分实付和公开标价；确认费用没有重复归属。
2. **work**：核对任务开始前目标与材料规模、变更记录、全部验收结果、模型及 Harness 归因，以及声明的计时和事件。对于人工标准，由不参与该次提交的验收人按已登记量表检查。
3. **coverage**：核对整个连续范围中的付款、调用和任务清单，确认没有遗漏失败或未完成记录；签发稳定来源与稳定账期代号。
4. **quota**：读取供应商侧完整额度快照与活动，排除其他设备或用户、恢复量、重置和重叠窗口，核对消耗百分比和对应调用。

检查未完成就把对应项设为 false，不得由一个成功的检查替其他维度背书。

## 5. 本轮代码核查结果

1.1 要求采集器遍历全部层级代理，逐类声明事件与资源覆盖，分开记录直接费用和父级累计费用。程序校验树、事实去重、字段约束和金额守恒，不会自动提升 C1/W1 为独立验证等级。核验方应检查原始连续范围、遗漏后代、共享费用去重、失败保留及执行前分类依据。字段白名单、随机 UUID 和加盐摘要排除直接内容上传；预览还须核对公开产品标识，不能把格式正确等同无法重新识别。

2026-10-10 的针对性核查发现并修复：

- 总排名曾跳过零验收分组，可能只留下某模型的成功条件；现保留失败分组与未达标模型。
- 大组中的时间或事件数据可能只来自极少数人；现对每项可选测量独立检查发布门槛，总榜要求测量覆盖完整。
- 用量适配器曾把缺失值视作零；现保留 null，无 Token 的工作仍能按实付分析。
- 进行中范围可能被当成已结束的低完成率记录；现整期保留个人分析，避免选择性取出成功任务。
- 证明未绑定提交持有人，换 nonce 也不能识别同一真实周期；现加入 contributor、coverageRef、事务内唯一索引和签名留档。
- 费用核验可能被误当成额度核验；现额度单独授权并要求 Q2，金额环比核对价格快照。
- 相同份数但材料规模差距很大的任务可能进入同组；现固定计量单位和规模区间参与分组。

对应可执行回归位于 `tests/core.test.ts`、`tests/api.test.ts`、`tests/integrity.test.ts`。这些检查验证本地实现，不证明运营方已经接入真实账单或独立执行服务。

## 6. 外部能力与运营流程

当前已经实现证明接收与验证协议，没有接入实际独立验证机构、供应商私有账单连接或独立执行集群。服务器选定后才能完成运营部署，不能把本地签名测试称为真实用户数据已经核验。

新增的通用监控已能读取用户指定文件或 JSON API，但具体服务的适配和权限仍需用户配置；这不改变上述独立核验边界。AI 提示词、系统提示词和本机用户都可能伪造首次输入。程序的字段白名单、守恒、去重、范围与签名校验不执行这些输入中的指令；它们仍不能凭空知道一项任意工作是否实际完成。因此自报保留 C1/W0/Q0，公开可信资格需要独立证据。

监控以追加式本地记录和加盐哈希链检查留存后的修改，上传附带链头，服务器保留既有链头并拒绝倒退或不连续链接。本地整条链及尚未上传的事实可以被掌握本机的人重造，所以哈希不提升证据等级。后台只在按需 verify 时扫描整条历史，不在每次轮询重算。订阅 API 固定为本人可见 Q0，限额依据服务器接收时间，不能通过伪造旧时间绕过。

上线后的核查顺序是：保留异常记录和证据 → 限制其公开影响 → 在用户授权范围内核对账单与工作材料 → 记录原因、检查人、时间与处理结果 → 决定是否恢复公开统计。异常只表示需要核查，不直接宣布用户作弊。当前极端调用量和异常尝试次数会标记为待核查，不进入公开榜单；运营处理界面、人员和独立证据服务仍需接入。

同一访问来源每日最多保存 30 个账期，HTTP 请求按来源 IP 限流。部署在反向代理后，需要按真实代理网络配置可信转发与边缘限流；不信任任意客户端的 X-Forwarded-For。密钥准入、轮换、泄露处理、备份、异地恢复与运营联系渠道在部署阶段落实。
