# 分领域评价体系草案

2026-10-12 更新：已按原始论文和官方资料完善到16个工作领域、249个细分活动，另列42个学科和23个跨领域要求项。资料、阅读范围、实际覆盖和未标定边界见 [论文依据与实施说明](difficulty-research.md)。当前生产评分仍关闭，新增本地审阅模块默认关闭；显示要求与覆盖，不输出难度分或等级。

新版支持可选本地 `workItems/workGraphs`，由程序生成 `workStructure` 与去重成果；原图和成果身份不上传。`executionScope` 去重跨目标共享代理，每任务参与数与全局独立身份数分开。`task.requirementClassification` 可选保存原要求的子类型、学科、用途和依据，`componentTypes` 保存混合目标构成，未知和缺失不补历史。类型参与可比条件，难度不参与；混合构成不完整时不进行精确排名。

当前状态：`domain-difficulty-draft-2`，**未启用、未经真实任务校准**。当前采集协议为 `work-summary-1`，只记录任务类别、实际完成量、验收和执行消耗。上传模板、自动整理、预览、比较及排名均不计算难度。历史 `work-1` 原始字段继续保存，但不再影响当前分组。

机器可读规范在 `shared/difficulty-framework.ts`，任务目录在 `shared/work-taxonomy.ts`。只读接口 `/api/difficulty-framework` 返回草案及关闭状态；`/api/work-taxonomy` 返回任务类型、单位和验收说明。读取草案不会启用评分，提交字段或查询参数也不能启用它。

## 1. 评价对象与边界

评价对象是原始要求确定的独立目标。软件、研究、写作等名称只确定领域，不能确定任务难度；同为“登录功能”，本地登录表单、多角色授权、跨租户隔离与旧账号无停机迁移，所需成立的条件不同。

领域下面是具体工作子类型。例如软件工程分为需求、架构、界面、服务、移动端、数据库、集成、并发、缺陷修复、性能、安全、重构、测试、部署、观测、工具、文档和维护。实现语言、模型名称与软件名称不充当工作类型。

体系覆盖以下领域。子类型代码、完整名单和允许单位由同一目录提供；不在目录中的工作保留 `unknown`，新增类别须增加版本，不强行套入相近专业。

## 2. 六组相互独立的信息

1. **问题与必要方法要求**：领域内必须满足的推理、构造、诊断、识别或证明义务。每个领域提供四个判断条目，每条有四段具体描述，用于未来评审选择；这些描述的序号不是得分。
2. **规模**：输入材料规模、独立对象数、事先要求的成果数。大批量重复处理与单个有复杂约束的问题分开。
3. **不确定性**：缺少哪些必要材料，证据是否相互冲突，原要求是否有歧义。未提供材料为未知，不能根据模型失败补写“材料困难”。
4. **验收要求**：正确性、覆盖范围、边界条件、可复现性、视觉或专业质量要求。风险、时限另列，不自动提高问题本身的难度。
5. **耦合结构**：需求部分的有向依赖、共享状态和反馈关系，以及是否必须整体整合验收。工具调用、重试、代理数量不充当耦合程度。
6. **环境条件**：可用工具、网络、权限、环境准备、已有上下文与可复用材料。环境受阻需独立记录，不能当作模型能力差或任务本身困难。

多组信息存在相关性。例如并发正确性已经属于软件的不变量条目，就不能把同一约束再以“研究性”“创新性”加分。领域内判断条目以描述和证据为主，不继续使用旧版五项相加的 0–11 分。

## 3. 方法要求与实际方法

未来 `requiredMethods` 只记录原要求明确指定，或根据问题性质有证据证明必须满足的方法义务。`usedMethods` 是执行事实，区分最终采用与尝试后放弃。没有方法记录为 `null`；实际检查过且没有特定要求才为 `[]`。

使用 Transformer、整数规划、系统综述或因果推断这些名称，均不自动提高难度。自行选用复杂方法也不会改变原任务要求。判断的是方法在当前问题中的成立条件，例如：

| 同名任务 | 需要区分的要求                                         | 不能用来判断难度的指标     |
| -------- | ------------------------------------------------------ | -------------------------- |
| 登录功能 | 角色与租户、身份来源、状态恢复、旧数据兼容、不停机要求 | 文件数、代码行数、代理数量 |
| 预测分析 | 时间依赖、目标数量、泄漏控制、分布变化、验证范围       | 训练轮数、超参数尝试次数   |
| 最优路线 | 容量、时间窗、多仓、取送关系、随机需求、最优性证明     | 求解器耗时、节点搜索次数   |
| 文献综述 | 来源筛选、证据质量、冲突结论、综合规则、可复现范围     | 检索次数、引用数量本身     |
| 翻译     | 歧义、专业术语、文化语用、占位符、字幕时长             | 输出 Token 或反复重译次数  |
| 设计页面 | 信息关系、交互状态、适配范围、无障碍和使用验收         | 像素数、生成候选数量       |

当前 `work-summary-1` 不采集上述方法判断，不为补齐未来字段重读历史。

## 4. 混合任务与大量耦合部分

一个共同验收目标保持一个稳定根任务标识。其组成部分按原需求的交付边界确定，不能依据后来开了多少个代理、写了多少文件或调用了多少工具拆分。

未来评审按以下规则处理：

1. 每个部分选择自己的领域、工作子类型及适用判断条目；跨领域任务允许多个部分分别评审。
2. 原始目标、部分身份和依赖边留在本地。上传只使用版本化类型、计数和经过检查的结构摘要，不上传题目、业务名或内部系统名称。
3. 有向依赖、共享状态、反馈边分开记录。存在循环时保留反馈事实；只在计算依赖深度时将强连通部分视为一组，不能删掉循环冒充独立工作。
4. 保留各部分的判断向量及整体整合要求。不能把不同领域的描述序号相加，也不能取一个平均数掩盖关键部分的缺项。
5. 子部分完成量、整合验收与根目标验收分开。100 个部分归属一个共同验收目标时仍只有一个根目标；缺少关键整合验收时不能报告目标已经通过。
6. 修改计划保留版本与变更依据。追加需求可增加计划工作量，但不能把重复劳动、重试或换方法冒充新增目标。

当前只登记组成部分数、整合验收事实及 `completedWork`。未知的具体完成分布保持未知，不按总体完成比例猜各类成果数量。

## 5. 将来如何形成分级

当前程序只发布描述规范，`scoringFunction` 和 `levelThresholds` 均为 `null`。没有偷偷运行的实验分数、跨领域总分或自动开启开关。未来启用采用以下程序：

1. 冻结领域、子类型、判断条目、样本计划及验收标准。在收集标签之前确定修改与发布条件。
2. 取得真实且已授权的原始任务要求。至少两名领域评审独立判断，隐藏模型、Harness、费用、Token、轮次、耗时、尝试次数和最终结果。
3. 对每条记录“描述序号或未知、证据类别、覆盖范围、评审状态”。未适用与未取得依据分开；不把未知当最低档。不以 AI 自报的 high confidence 当正确率。
4. 报告逐条一致率、序数分歧、缺项率及覆盖的任务子类型。集中修改造成分歧的描述，再用没有参与修订的真实材料检验。
5. 按来源和任务家族划分校准与检验材料。同一目标的改写、同一模板的近似任务不能跨集合。通过随机打乱执行信息，检查判断是否被高 Token 或失败结果影响。
6. 只有在单个领域和子类型上取得稳定证据后，才确定其组合规则与阈值，并同时公开版本、适用范围、评审一致性和检验结果。尚未覆盖的领域继续保持未校准。
7. 即使将来启用，难度也只用于有共同要求的比较条件。费用不除以主观难度分，完成率不再乘一遍，不把“更难”当成果价值奖励。不同领域同名等级不能直接比较。

这些是待执行的校准要求。本轮没有标注真实校准数据，也没有声称识别准确率。程序检查只能验证关闭状态、字段和计算规则，不能证明语义判断准确。

## 6. 当前完成量摘要

`evaluation.completedWork` 按 `kind + workType + unit` 记录；无法细分时 `workType='unknown'`。已知同类同单位合并成一条，每条包括：

| 字段         | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| `planned`    | 原始要求中计划数量；没有事前依据为 null                      |
| `completed`  | 去重后的实际完成量；未测量为 null                            |
| `accepted`   | 已核验通过的完成量；不得超过 completed；未验收为 null        |
| `source`     | 成果检查、执行日志或人工报告；来源标签本身不是可信证明       |
| `acceptance` | 自动、人工、二者都有或未知                                   |
| `coverage`   | complete、partial 或 unknown；partial 的数值仅代表已观察部分 |

章节、接口、记录、媒体秒数等分别汇总，不转换为统一工作价值。重导出、重编码、同一内容反复修改、父子代理重复处理不得增加最终成果量。完成量不参与排名分组，避免以完成结果筛选样本。

预览的 `evaluation.summary` 同时提供根目标各状态数量、完成量覆盖、分单位完成量、输入/缓存/输出/思考 Token，以及真实轮次和代理记录。每个可加计量保留 `total`、`knownSubtotal`、`measured` 和 `expected`：不完整总量为 null，已知小计不会被冒充总量。最大代理深度和每任务最大并行数不相加。缓存 Token 属于输入，思考 Token 属于输出，总 Token 只加输入和输出。

摘要突出已完成成果，但失败、部分完成、放弃、返工以及全部后代代理的调用和费用继续保留。采集整理自己的消耗单列在 `collectionProcessing`，不能成为新的成功业务任务。

## 7. 历史、隐私与防虚构

旧记录不改写、不删除、不重新收费。新的统计投影忽略旧主观难度字段；不能修改旧知识、新颖性、置信度等标签来改变当前分组。旧版预先聚合的难度分组无法逆推出原始样本，因此不进入新版模型排名，需要从保留原始记录重新聚合。

固定类别、数量和公开产品信息继续执行字段白名单、来源门槛和独立证据规则。细分类型只在私有明细中出现，公开接口不会把单条细分成果列为社区样本。文档、源码、提示词、业务标题、原始证据、路径、账号与专业敏感内容留在本地。

稳定本地标识、加盐摘要和幂等回执用于防重复与发现内容变化；不能证明最初的任务量真实。人工报告和 AI 提取必须保持原证据等级，不因写成“已验收”“精确”或用了复杂方法而升级。没有独立证据就不宣布经过独立核验。
