# 跨次完整结算修订

初版：2026-10-14；本次更新：2026-10-15。协议 `settlement-revision-1`，公共事实编译器 `public-facts-11`。对应优化清单 L-01 至 L-05、C-01 至 C-04 的部分基础工作。已经接入协议、入库、当前统计、私人反馈、历史列表及本地客户端；投入真实服务的状态以 `status.md` 为准。

## 完整快照替代

新记录明确替代同一持有人、同一账期、全部根目标和原要求版本的整个旧记录。每项费用旧40、新100时，当前记100，不相加成140，也不把100理解为新增差额。整个快照的范围完整不等于费用证据完整；新版费用或任务仍未结束时，比较资格仍会停止。

`settlement` 保存协议版本、固定范围 `whole_record_snapshot`、修订号、父回执 ID/digest/修订号，以及每项根目标的本地随机要求引用和版本。修订0没有父记录，后继为父修订号加1。要求引用不含原要求文本及其哈希。完整记录的 digest 覆盖声明，不证明原始事实真实。

服务端认证确定持有人。账期核对 origin、随机账期 ID、月份、币种、计费方式、套餐及版本和订阅引用。要求结构核对全部根目标、工作类别、范围、输入背景、验收方法及必需条件数、依赖、需求锁定、计划、分类与结构画像。结果、费用、用量和执行配置允许修正；不能删掉失败条件、缩减根目标或改变要求范围后继承旧引用。独立证明须绑定新版 digest，不继承旧证明等级或 nonce。

旧记录可以明确父回执首次绑定为虚拟修订0。缺父回执、摘要不符、跨身份或范围不一致时拒绝替代；未声明的重复结算保留原冲突规则。同一原要求的重开和后续终态可以作为结果与累计费用修订；新增 [要求历史](requirement-history.md) 保留原验收及当前重开，并暂停相交旧结算。跨要求版本结算、差额记录、跨期退款及多条链合并尚未实现。

## 当前统计与历史反馈

原始正文、回执和已保存反馈保留。当前统计采用已校验链头，再判断公开同意、证据、费用完整性和比较条件。公开旧版被私人或未核验新版替代时，旧版也不再上榜；新版不因此取得公开或独立核验资格。

新接收记录分配单调正整数 `receivedSequence`。本人反馈的任务检查和窗口采样采用自身接收截止，同一毫秒内后来的记录不会倒灌。旧记录没有序号时仍按原接收时间处理，不重写正文。首次读取旧回执按它自己的前缀评价；冻结报告保留原文、数值、参照快照和生成时间。

缺父或冲突链不能解释为不存在。与当前根目标相交时停止单位成本比较和推荐，无关目标不因此扩大阻断。相交链还在准备时返回 pending，不冻结临时未知报告；确定缺失保留 unknown。可信关系投影只保存随机根目标 ID，不公开私人金额、正文或时间线。

“我的记录”显示当前、已替代、待确认或冲突，保留全部版本。月度合计排除已替代和关系未确认版本，不把缺项填零。未关联记录的范围仍可能重叠，合计不能称独立任务总量或去重账单。分页附本人历史 revision；期间发生变化时提示刷新，不拼接不同状态。

## 显式本地准备

普通上传不自动增加协议。用户要修正已上传记录时，在“我的记录”下载修订依据；文件是单条私人详情，不含访问密钥，也不公开分享。

```text
npm run contribute -- settlement-start --input record.json --out NEW-record.json
npm run contribute -- settlement-revise --previous revision-basis.json --input updated-record.json --out NEW-revision.json
npm run contribute -- prepare --input NEW-revision.json --out NEW-preview.json
```

首次命令为尚未上传的记录生成随机引用。修订命令校验父正文 digest 和服务端当前状态，复制原要求引用并比较结构。只写新文件；不读取身份、扫描历史、查询账户、调用模型或上传。`prepare/submit` 仍执行预览和摘要确认。下载后父版本已经变化时，服务端最终校验返回409；客户端检查不替代它。

## 入库与资源边界

数据库结构版本6。接受元数据保存链头、成员原摘要、正文 SHA、接收时点和序号；正文 SHA 只在服务器内部保存。修订采用独立唯一槽位，同时保留原经济指纹及查重约束。同修订同内容换请求键返回原回执和原序号；不同内容或证明返回409，每条记录最多1000个请求别名。

正文、证明、回执、成员、链头、预算和失效标记在同一事务提交。按期望父回执条件更新，不采用最后写入覆盖；容量失败一起回滚。外部 UPDATE/DELETE/REPLACE 将变化或消失成员标待确认/缺失。唯一键替换捕获最多三个冲突旧行及改 ID 的旧行，IGNORE不删除既有成员；后续只核对变化输入。

初始化增加元数据表和索引，不回填全部历史正文。公开事实沿用128条/2 MiB分批和首条4 MiB预算，编译版本变化按既有有界流程准备。活动根成员只移除旧/新两个链头，不逐次扫描全部修订。列表一次索引关联与两次本人修订号核对，不逐条查询正文，不新增轮询。
