本次增补：[选择侧重选稳定性](selection-stability.md) 已接入新离线评价报告、网页及私人反馈。它在原选择分区重新选择有限支持配置，保留全部重复与未知；不改变下文冻结后评价的方法或旧报告，也没有完成未来时间评价及选择过程的总体推断。

## 两种问题分开回答

现有榜单回答“当前已观察同类任务中，该模型在哪个 Harness 的单位验收费用最低”。它按固定任务构成计算，不按完成率档位筛选。选择后的独立评价回答“按预先确定的规则挑出的模型与 Harness，在未参与该选择的数据中表现如何”。两种数值分别展示，不能用独立评价结果为使用全部数据重新挑出的现榜赢家贴验证标签。

先接入同一就绪事实快照的来源留出：固定目标、算法及分组规则，按持有人与可信来源的已知关联组成组，整组进入选择集或评价集。关联图可使用可信私人来源证明，原ID和关联边只在内部处理，不进入公开报告。没有证明的自报来源不能合并陌生身份。相同持有人的根目标、账期和全部修订不得跨两组；来源组数不能称独立真人数，未知任务族相关性仍需说明。

划分种子由固定算法标识、完整费用/证据范围和月份确定；改目标名称、时间、任务类型或来源摘要不会重新抽取一套划分。组标识只保存在私人准备文件，公开结果仅含划分摘要。分组使用来源关系闭包，私人中间持有人也参与连接，不通过公开记录直接共有一个来源的局部关系代替完整关联。这里是回顾性来源留出；目标条件来自既有公共快照，不能称为事前注册的未来预测试验。

时间留出使用独立协议。在 T0 保存固定目标、已选择模型/配置以及最小必要的当时事实快照，T1 才取得评价。当前事实表的链头、证据及公开资格会随修订变化；只按 created_at 过滤，无法重建 T0。当月条件也不能直接套入未来月份；跨月适用规则须明示，新模型或新 Harness 版本不继承验证。此路线不能借来源留出先宣称完成。

## 选择冻结后再评价

选择集复用现有每模型、每条件最低 Harness 规则。目标条件与权重必须先固定，不从评价结果改变任务组合。保存每个条件的完整配置：供应商和模型版本、Harness型号/版本/variant/surface、套餐及版本、模式、工具、推理和缓存。候选模型范围、选择集的主赢家及并列同时冻结。

评价器只匹配这些配置，不能再次调用最低 Harness 选择器。匹配配置缺数据或失去公开发布支持时保留缺项，不换成评价集更便宜的配置、不删除条件、不重新分配权重。评价集排序只作为探索性描述；主结果说明选择集原赢家的留出表现，不在评价集再挑一个赢家后称其独立验证成功。

零验收也有已知支出。对每条件 s，分别保存已结束根目标数 n、全部归属支出 c、验收数 a 和固定权重 q。根目标是可以单独验收的工作要求；协议中的 independent 不表示已经证明其统计独立。完整条件覆盖时计算：

```text
平均每个已结束根目标支出 = sum(q_s * c_s/n_s)
标准化验收比例   = sum(q_s * a_s/n_s)
单位验收费用     = 前者 / 后者
```

等权两条件各20次、各支出200，验收数0和20时，平均发起支出10、验收比例0.5，总体比值20。第一条件的失败不能被删除，也不能因单条件无成功就抹掉合法总体比值。全部条件零验收时保存已知分子和零分母，费用为无法有限估计，不填零、不删失败样本。总体比值描述固定发起组合，不能保证所有条件都能验收或完成一份指定工作组合。

## 运行和公开边界

采用显式离线批处理，不在每次网页访问重建关联图、拟合或重新分组，不新增轮询。只读取已就绪的数值事实和必要身份关联，不读取原始提示词或代码。关联扩展、记录数、条件展开和结果字节都有整体预算；触顶返回容量不足，不截断数据继续评价。

一次评价记录任务目标、规则版本、划分摘要、选择定义、事实版本、证据发行方版本、来源截止和计算时间。原始报告与选择文件不可覆盖。网页/API/导出共用报告状态；快照或目标不一致时不把旧评价映射给当前赢家。未配置或支持不足显示尚未独立评价，不生成额外用户等级、通用难度或未来节省保证。

事实版本纳入持久数据世代；每次被跟踪输入变化、发行方或编译器换代，在同一事务生成新的随机世代。新实例及同一备份正常写入后形成的分叉，即使版本计数相同，也不能挂接对方报告。这是数据版本识别，不是对任意数据库管理员直接篡改派生事实的认证。旧数据库仅迁移固定大小状态和触发器，不为此重新扫描正文。

准备文件的 SHA-256 用于一致性检查。执行时还在同一事实快照中重建固定分组和选择侧决策，并核对接收序号；编辑后重新计算哈希也不能更换这些计算规则。接收序号是准备时观测的全库时点，不是用于重建历史事实的查询过滤器；严格相等会使准备后新增无关私人记录也要求重新准备。建议使用一致性备份的只读副本，以获得稳定的批处理范围。

每个分区每个配置重新检查至少20个已结束根目标、5个已知关联组及最大组任务占比35%的公开门槛。模型在评价侧缺少完整支持时，连选择侧费用和已测分项也隐藏，防止与全量统计相减推回缺失部分；保留模型及“支持不足”状态。门槛是本项目发布政策，不是论文给出的充分样本量。

## 管理命令与历史

需 Node.js 24，并显式指定本地文件；不采用默认用户数据库路径，不调用模型或网络。

```powershell
node --import tsx scripts/ranking-study.ts prepare <一致性只读副本.sqlite> <目标集合.json> <新私人准备.json> <目标ID>
node --import tsx scripts/ranking-study.ts evaluate <一致性只读副本.sqlite> <私人准备.json> <新私人报告.json> <新公开集合.json>
node --import tsx scripts/ranking-study.ts validate <公开集合.json>
node --import tsx scripts/ranking-study.ts publish <公开集合.json> <发布目录>
```

准备和评价是两个显式动作。计算在独立子进程运行：30秒超时、V8堆256MiB、SQLite原生分配128MiB并读回确认，数据库缓存8MiB。它们不是整个进程RSS硬上限。记录最多20000、关联节点30000、证明关系100000、关系读取200000、条件元数据50000行/16MiB、准备与结果各8MiB。基础评价达到边界整次失败；附加重采样超出自身预算时保留完整基础评价，整份附加分布标记未计算。无自动重试、截断结果或后台定时任务。

只读连接不创建或迁移数据库；临时分组表留在该进程内存。文件完整写入并同步后，通过同目录硬链接以不覆盖方式发布；文件系统不支持则失败，不降级为覆盖。私人准备含内部关联标识，私人报告含完整目标，禁止上传到公共目录。0600在Windows不能代替目录访问控制，管理员应将它们放入受控私人目录。若两个输出中后一个失败，已经成功保存的私人报告保留，重新运行需选新输出名称。

发布保存报告、完整集合及 `(targetId,dataVersion)` 的永久登记，最终原子更新 `active.json`。同一目标与事实版本已登记后，不允许产生另一份结果；在更换到新版本、又退回旧数据之后也不能换报告。活动集合每目标一个报告、最多128个，超出失败，不自动清理历史。发布锁意外残留时，确认没有发布进程后再处理。该格式本轮首次接入；旧实现的非活动历史不会自动补建登记，导入外部归档前须另行核对。

部署时设置 `RANKING_STUDIES_FILE` 为公开活动集合的绝对路径，与 `RANKING_TARGETS_FILE` 配套；默认留空。服务只在启动读取和验证，不监视文件或轮询。`boards-13` 的模型总榜和类型榜带 `independentEvaluation`，当前事实版本与目标完全匹配才给出公开报告。`rankingStudiesVersion`进入缓存与导出；私人文件不进入接口或贡献工具包。首页和比较页共用评价面板，桌面私人反馈尚未采用这套来源留出结果，不能将本轮网页接线称为桌面评价完成。

首阶段不输出未经实现的置信区间或稳定名次。现已增加固定选型后的来源组重采样和零分母分类，详见 [方法与实验](ranking-resampling.md)；逐组删除和集中度公开档位见 [来源影响](ranking-source-sensitivity.md)。成组时间块、选择全过程稳定性和经过校准的推断方法仍待推进；不能把来源分布四分位、经验重采样范围或删除影响直接改名为置信区间。

## 研究依据和采用范围

[Cawley与Talbot，JMLR 2010](https://jmlr.org/papers/v11/cawley10a.html)说明有限样本上的选择准则可能过拟合，并使后续评价产生选择偏差。这里采用选择与评价隔离，不套用论文实验的数值作为OpenCost精度。

[AI Agents That Matter，2024](https://arxiv.org/abs/2407.01502)讨论成本与效果共同评价、留出不足和可复现性。这里保留费用与验收、人工投入分别展示，并固定选择和报告版本，不据此宣称全市场最优。

[scikit-learn官方交叉验证文档](https://scikit-learn.org/stable/modules/cross_validation.html)区分成组划分和时间依赖划分，并指出在测试集调整配置会发生信息泄漏。这里借鉴设计原则，继续使用本项目TypeScript与SQLite；未引入新的模型库，也未使用`cumcm-statistics`。
