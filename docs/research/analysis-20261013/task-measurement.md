# 任务难度、工作量与真实环境评分：研究和迁移方案

检索及核验日期：2026-10-13（Asia/Shanghai）。本文是定向资料研究和实施设计，不是穷尽性系统综述。机器可读记录见 [task-measurement.sources.json](task-measurement.sources.json)。既有的 [跨领域研究](../../difficulty-research.md)、[分领域框架](../../difficulty-framework.md)、`shared/difficulty-framework.ts` 和 `shared/difficulty-profiles.ts` 已阅读并作为起点；16 个领域、249 个活动、学科分类与原有要求条目继续复用。

**实施结论：先补能证明工作事实、比较条件和信息缺失的脱敏字段，再做分组统计；难度评分继续默认关闭。** 难度框架保留为可选研究模块。本轮另实现默认关闭的本地 Rasch 试验库，仅对调用者声明的公开共同任务矩阵计算描述性参数，尚未取得真实校准数据。现阶段不应把任意权重加总成“客观难度”，也不应拿难度分去除费用。本研究分工没有改动生产调用、采集开关、实际用户记录或评分状态。

## 1. 要测量的六件事必须分别保存

| 对象         | 定义                                                   | 形成时间                   | 示例                                   | 禁止替代它的指标                   |
| ------------ | ------------------------------------------------------ | -------------------------- | -------------------------------------- | ---------------------------------- |

| 完成工作量   | 去重后已经交付、验收的成果与根目标                     | 执行后                     | 1 个已验收需求、3 个已验收独立场景     | 字数、Token、提交次数自动折算成果  |
| 执行负担     | 为完成要求实际投入的资源与人工干预                     | 执行中和执行后             | 全部后代代理费用、重试、等待、人工审阅 | 任务固有难度                       |

| 经验难度     | 固定任务分布、环境、预算和验收下，由交叉试验估计的参数 | 独立标定后                 | 某领域共同任务的 IRT 参数及区间        | 某用户一次失败、人工猜测、领域名称 |

Wood 把组成、协调和动态复杂度分开；Campbell 的出版社摘要也强调区分任务属性和通常混用的其他属性。Campbell 正文未取得，因此本文不引用其具体四项定义或公式。[Wood，1986](https://www.sciencedirect.com/science/article/pii/0749597886900440)、[Campbell，1988](https://journals.aom.org/doi/abs/10.5465/amr.1988.4306775)

METR 的真实开发者试验先固定任务再随机分配是否使用 AI，明确指出代码变长、把一项工作拆成多个任务，都能提高计数而不提高真实生产率。OpenCost 应保留原根目标和要求版本，并把原范围、后续新增范围、修复返工分别登记。[Becker 等，2025，§1–2](https://arxiv.org/html/2507.09089v2)

## 3. 可以新增的脱敏字段

这些是**候选字段**，须经过协议和隐私审阅再决定收集。默认关闭、用户预览；使用封闭枚举、布尔值、粗粒度区间和计数，不增加任务原文、自由文本摘要、文件名、路径、网址、仓库名、客户、账号、内容哈希或语义向量。单字段不含姓名不代表组合后不会识别个人；稀有组合应粗化或停止公开聚合，私人反馈与公开榜单要有不同发布门槛。

| 候选信息           | 脱敏表示                                                         | 能增加的分析                       | 采集与解释约束                                     |
| ------------------ | ---------------------------------------------------------------- | ---------------------------------- | -------------------------------------------------- |
| 要求版本与形成时间 | 随机本地关联号、before_execution/original_request_review/unknown | 判断事前分类是否受结果污染         | 历史回看不能升级成执行前登记；原文哈希不上传       |
| 范围变化           | 原范围/追加需求/缺陷修复的计数及对应状态                         | 区分加需求与模型返工，解释成本上涨 | 根目标不因对话轮数增加而分裂                       |
| 指令显式程度       | 目标给定/步骤给定/需检索规则/未知                                | 同一活动不同信息条件的结果比较     | 不能按提示词长度推定                               |
| 上下文与复用       | 原始材料完整度、既有模板/资产/代码是否可用、上下文新鲜度区间     | 冷启动与复用差异、上下文缺失关联   | 不保存材料名、技术栈细串或精确缓存文本             |

| 验收协议           | 程序测试/人工复核/形式验证/状态核验/自报；版本及覆盖             | 同一验收强度下比较；验证器缺口     | 通用公开协议可用注册 ID；私有检查名不上传          |

| 执行阶段资源       | 计划/生成/工具/验证/修复/等待的 Token、费用与时长小计            | 成本结构、验证投入、返工关联       | 阶段只用可验证事件映射；未知归 unknown，不强凑总额 |

| 任务族             | 同一用户同一窗口的随机关联及族大小；公开基准 ID 另列             | 族内相关、批处理与独立任务数差异   | 私有语义相似性留本地；无跨用户同题证据就不称同题   |

| 采样方式           | continuous/selected；窗口和失败/取消/未完成是否纳入              | 识别上传选择偏差、观察不完整       | “完整”只限授权采集范围，不推断整台机器或全部工作   |
| 终止原因           | 验收完成/预算耗尽/超时/用户取消/环境失败/不适用/未知             | 失败、停止、阻塞和未观察分开       | 超时与取消不能从统计中静默删除                     |

程序能从 Harness 事件直接取出的字段优先；语义要求的识别仍需本地 AI 或用户确认。全脱敏之后只能利用已形成的结构字段，服务器不能再凭计数复原业务语义或“补全”缺失要求。

## 5. 可选经验标定算法

### 5.1 从最小可识别设计开始

为每个需要标定的领域建立公开或经许可的共同任务库：同一要求版本、验收协议、环境快照和预算，由多个模型 + Harness 版本交叉执行。私有任务只有一次执行时，失败既可能来自题难、配置弱、信息不足、环境受阻，也可能来自验收误判；这些因素不能仅凭结果分离。

基本参照模型为 `Pr(Y_ic = 1) = sigmoid(theta_c - beta_i)`，其中 `c` 是完整配置而非裸模型，`i` 是任务版本，`Y` 是约定验收结果。量尺原点必须固定；缺少共同任务的连通组分别标定，不能硬拼排行。Rasch 的分离与不变性依赖参考框架和模型拟合。[Wright/Linacre，1987](https://www.rasch.org/rmt/rmt11a.htm)

任务包含多个要求维度时，候选模型为 `Pr(Y_ic = 1) = sigmoid(a_i^T theta_c - b_i)`。载荷、维数、补偿或非补偿关系需按领域实验检查；“一个强项弥补所有关键缺项”不一定符合实际验收。已声明的关键约束失败仍保留为失败，不能靠别项高分抵消。[Chalmers，2012，§2](https://www.jstatsoft.org/index.php/jss/article/view/v048i06/598)

用于预测新任务的研究扩展可以采用分层解释性模型：`beta_i = f_domain(x_i) + u_family + u_task`；`x_i` 仅含事前要求与环境字段；模型与 Harness 可在充分交叉数据下分解为效应，否则保持联合配置。这个式子是本项目的迁移设计，不是已拟合模型，不采用手定“文档=1、代码=3”的权重。

### 5.2 人类时间只是候选锚点

METR 的形式为 `p_success = sigmoid((log h_config - log t_task) * slope_config)`；`t_task` 是合适人类基准成功耗时，`h_config` 是 50% 成功位置，不是 AI 实际运行时间，也不是保证能完成的最长任务。原论文同时指出人类基准成功选择、熟悉程度和任务分布的限制。[METR，§3、E.4](https://arxiv.org/html/2503.14499v4)

2026-10-08 的 Nguyen/Fithian 预印本把时间到潜在难度的关系改为单调样条，加入任务族效应和重复试验过度离散，并在留出数据上比较 Brier score、log loss 等规则。适合迁移的是**检查非线性、相关性和校准**，不是复制其已发表样本的系数。本文未复现该论文结果，也不将预印本等同已通过同行评议。[方法 §2–3](https://arxiv.org/html/2610.12466v1)

### 5.3 上线前的最少校准证据

1. 按任务族、贡献者和时间划分训练/验证，不能把同题重试随机拆到两侧；原要求识别误差也须进入检查。
2. 与“按领域/细类平均成功率”的简单基线比较，检查 Brier score、log loss、校准截距/斜率，以及关键子组误差。训练拟合优不能代替留出表现。
3. 检查任务族和重复运行的局部依赖、模型/Harness 交互、语言和环境差异项功能。样本不足的维度返回未知或宽区间，不能靠高复杂模型补造证据。
4. 分离需求不可满足、验证器故障与配置未成功。保留尝试和费用；分别给出按原分配目标的服务结果与验收有效子集诊断，公开排除原因及分母。
5. 每次发布固定 `calibrationVersion/referencePopulation/domain/period/protocol/parameterUncertainty`，保持原始摘要和旧参数快照。新版本不覆盖旧记录时点的解释。

验收标准、用途、人群和分项解释需要分别验证；本文不设无数据依据的“至少 N 条就准确”的万能门槛。[AERA/APA/NCME，2014，标准 1.0–1.17](https://www.testingstandards.net/uploads/7/6/6/4/76643089/standards_2014edition.pdf)

### 5.4 本地原型的最小正确实现

2026-10-14 增补：原拟合保留，结果第二版增加模型/Harness/任务设计诊断；新论文的核对、反例和采用范围见[编程任务难度资料核对](../coding-difficulty-20261014.md)。诊断不把配置能力拆分，不修改旧参数结果。

实现位于 `shared/difficulty-calibration.ts`，入口为 `calibrateDifficulty(input, { enabled: true, lambda?, maxIterations?, tolerance? })`。未显式开启即返回 `disabled`，不读取输入；它没有网络、日志、采集器、数据库和生产排名依赖。矩阵只接受版本化的模型、Harness、配置、领域、任务库、原要求、验收和执行协议，以及每个配置—任务单元的成功数和试验数；拒绝自由文本及额外字段。来源 URL 和公开任务清单哈希是调用者的声明，程序只校验格式，不验证来源真实性、公开性、清单内容或重复运行是否独立。

对任务 `i`、配置 `c`，令 `z_ic = theta_c - beta_i`、成功数为 `s_ic`、试验数为 `n_ic`。在约束 `mean(theta)=0` 下最小化：

```text
L = sum_ic [s_ic * softplus(-z_ic) + (n_ic - s_ic) * softplus(z_ic)]
    + lambda / 2 * [sum_c theta_c^2 + sum_i beta_i^2]
```

`lambda` 默认 1，可选范围为 `[0.001, 1000]`，属于明确记录的研究设置，没有宣称已经由数据选优。L2 令数值估计有限；它不能使缺少交叉、失败或成功的数据获得实证依据。实现采用受约束 Newton 法，求解约束方向并作回溯搜索，保持能力参数均值为零；不把全部参数同步平移后误称仍在优化同一个 L2 目标。使用稳定的 sigmoid/softplus，按投影梯度判断收敛。

开始拟合前要求反应图连通、每个任务至少有两个配置、每个配置至少有两个任务、整体既有成功也有失败。它们是防止明显缺少比较依据的最低设计条件，**不是统计可靠性门槛**。不满足返回 `insufficient`；未收敛返回 `not_converged` 且不返回拟合参数。行或列全部成功/全部失败时保留观测和边界标记，隐藏对应能力或难度参数；这些观测仍影响联合拟合，所以其他参数也需结合边界占比和正则设置解释。

正常输出任务的域内相对 `beta` 和 `sigmoid(-beta)`。后者是本次标尺上 `theta=0` 的虚拟配置通过概率，既不代表某个真实模型，也不等于各配置通过概率的算术平均值。没有输出 0–100 的普适难度分、置信区间、跨领域等级或生产费用乘数。改变配置集合会改变能力原点；跨期比较必须保留同一参照与协议，不能直接比较两次各自中心化的参数。

训练 LogLoss 和 Brier score 按试验数计算，明确标为 `training_only`、`not_validated`；Brier 按单次二值结果计算，不能用各单元成功比例的平方误差冒充。任务族和重复相关性只记录，尚未建模；声明“独立运行”也不是实际验证。未经按任务族分组的留出验证，拟合结果只能用于检查本地研究输入和方法行为。

为限制本地计算，原型最多接受 16 个配置、64 个任务、1,024 个单元、每单元 1,000 次试验、合计 100 万次试验，最多 100 次迭代。超长数组在逐项解析前拒绝。这些是计算上限，不是推荐样本量。`tests/difficulty-calibration.test.ts` 的 10 项专属测试已通过，覆盖独立一维驻点求根、对称矩阵、排列不变性、边界、断图、未收敛、无效输入和上限；测试使用构造数据，不证明现实任务的难度已经校准。

## 6. 工作量、任务评分与可靠性如何程序计算

**工作量使用并列量，而不是总分。** 原根目标总数、已经验收根目标数、部分成果的数量与单位、原范围覆盖、独立任务族数、执行尝试数分别报告。不同单位不加总；修订、格式变体、复制和多个代理重复记录只保留同一成果身份。复杂图保留有向依赖、共享状态和反馈关系；不能把循环删掉后宣称工作互相独立。

**验收可以输出覆盖区间。** 如果用户/协议在执行前声明验收项和权重，令 `W` 为全部适用要求权重，`P` 为已独立核实通过的权重，`U` 为尚未知结果的权重，可显示 `[P/W, (P+U)/W]` 和已检查覆盖率。它是“约定要求的满足范围”，不是难度或通用质量分。没有完整适用项分母、没有事前权重或验收项混粒度时，仅报计数；不能临时假设等权给出精确百分数。根目标是否完成仍按原协议，不能用平均分覆盖关键失败。

**重试和稳定性分别统计。** 在预先安排、环境重置和可视为独立同分布的重复试验中，任务有 `n` 次试验、`c` 次成功，τ-bench 的 `pass@k = 1 - C(n-c,k)/C(n,k)` 表示至少一次成功，`pass^k = C(c,k)/C(n,k)` 表示每次成功；最后对任务求平均。必须 `n >= k`，`C(a,k)=0` 当 `a<k`。连续对话修复不满足这组条件，只报告实际重试后的最终结果和全部费用。[τ-bench 方法](https://arxiv.org/html/2406.12045)

**费用继续用已验收根目标作分母。** 相同任务条件、同币种和同费用范围下，`全部归属费用 / 已验收根目标数` 已经把失败和重试纳入，不再乘一次完成率惩罚。分母为零时为不可计算，不能用任意小数替代；有费用缺项时只给已知小计与覆盖。付费金额、订阅分摊和 API 等价价不能混加。

**选择 Harness 不能择取单个最好结果。** 每个任务细类独立选候选配置；每个模型比较所有满足同一证据条件的 Harness 配置，给出最低验收单位成本的模型 + Harness。其余所有失败、已观测费用和不确定性均保留。候选多时用过去窗口选择、下一窗口检验，或留出评估，降低“看了很多配置后刚好选中幸运样本”的偏差。

## 7. 给用户反馈时应新增的内容

服务器先在有效公开范围中检索整个数据库，再依次执行时间截止、真实来源、同任务细类/组成、同验收口径、同费用定义、排除用户自身、隐私门槛和证据门槛。可以用多个资料层次帮助用户了解背景，但不能把放宽条件后的背景人群伪装为同类对照。

每条反馈至少附带：当前观测窗口、指标定义、分母和缺失率、参考人群条件、独立来源/任务族数、数据时间、比较区间、是否排除本人、是否为观察性关联。原始条目数大不代表独立证据多。

| 分析方向 | 用户可得到的信息                                 | 必须同时说明                             |
| -------- | ------------------------------------------------ | ---------------------------------------- |
| 工作组合 | 不同细类、领域和成果单位的份额变化               | 采集范围、混合任务缺项和单位不能相加     |
| 要求画像 | 哪些条件更常见：集成、兼容、证据冲突、隐式规则等 | 只比较已知事前标注；不是自动难度分       |
| 验收质量 | 首次通过、修复后通过、尚未验收、关键项未知       | 验收方法与独立性，不能由AI总结自证       |
| 成本来源 | 主/子代理、验证、返工、外部工具费用贡献          | 全后代覆盖、共享归属与未观测费用         |
| 时间负担 | 生成、工具、环境阻塞、人类等待与主动人工时间     | 各时间可能重叠，未知和并发不能直接相加   |
| 后续稳定 | 验收后重开、回滚、后续修改                       | 观察时长与未满窗口；追加需求不算缺陷     |
| 可靠性   | 同类任务的结果分布和重复试验表现                 | 各次是否独立、是否选最好、样本不确定性   |
| 配置选择 | 当前工作组合下可比较模型 + Harness 的费用区间    | 仅覆盖已匹配类型，未覆盖部分不给节省承诺 |
| 个人趋势 | 同一口径下近 7/30 天成本、验收和工作组合变化     | 区分任务组合改变、价格变化与配置变化     |
| 数据质量 | 哪些字段不足以支持比较，补哪类字段最有帮助       | 少数据时提供个人事实汇总，不填造社区排名 |

推荐必须标明“按当前数据库的可比样本估计”。没有随机实验或可信的因果识别设计，就不能把“同类样本费用更低”写成“换模型一定省钱”，也不能把个人成本高解释成个人能力差。小样本反馈可以丰富事实、覆盖和结构信息；不靠增加无依据的结论凑丰富程度。

## 8. 实施顺序与本轮边界

1. 优先新增无需模型推断的事件计数、覆盖、来源、终止、阶段资源和验收信息；用户可逐项关闭。
2. 在协议仍兼容旧摘要的条件下新增可选结构要求字段；未知历史不补写、不重新读原日志、不增加默认模型调用。
3. 先完成严格分组的多维统计、对照条件、反馈证据说明与缺失诊断。
4. 单独建设共同任务校准数据集，再决定是否开启经验难度。生产继续 `off`；选择查看研究框架不等于授权收集、上传或评分。
5. 当前文献映射没有覆盖全部语言、专业和未来 AI 使用方式；缺少任务专门证据时，继承领域要求画像而保持经验参数未知。`ghfind` 的项目身份、许可证和实际评分源码由平行项目研究负责，本文不猜测它的公式，也不将同名项目强行认作用户指定对象。

本研究分工交付文献记录、候选字段与评价设计，以及默认关闭的本地试验库。已经在构造矩阵上检查实现；尚未开展真实难度标定、跨领域校准、用户数据实验或生产难度评分。字段采集、统计反馈和界面整合由其他分工实施，以各自实际变更与验证记录为准。
