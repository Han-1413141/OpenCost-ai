# 每日任务分析、代码测量与存储

2026-10-16。每日工作日记现在可以关联本地要求分析、分项要求描述、代码快照和补丁数值。它们作为同一工作条目的可选分析保存，上传与后台运行仍按原授权执行，正式难度评分保持关闭。

## 四项能力

- 难度：沿用现有16领域、249活动的版本化要求表，保存有依据的分项描述位置、缺项和框架版本。界面明确标为实验，没有跨领域总等级，也不改变正式排名。模型或人的原判断仍是声明，程序只检查并映射规则。
- 任务复杂度：复用已有要求向量和依赖图算法。稳定要求单元先合并，重复边与共享状态组去重，再计算依赖深度、循环和协调结构；未知与部分覆盖保留。原图与节点ID留在本地。
- 代码：支持已有JS/TS、JSX/TSX与Python数值报告，按语言、算法、阶段和版本保留分布。JS/TS新增进程内数值缓存，内容、语言和解析器版本相同才复用。缓存最多16项、序列化数值总计1 MiB，采用进程内随机密钥的摘要索引，不保存源码、AST、路径或函数名；改变内容后重新解析。该上限不是全进程内存上限，退出后不保留缓存。
- 补丁：复用现有本地差异解析器和白名单投影，保留增删、修改块、文件操作与分散程度，不上传Diff正文。相同要求、测量族和阶段不允许多份报告叠加。

以上程序没有新增模型调用。需要AI辅助整理要求时，仍需另行授权所选Harness并计入它的用量，不会由这些命令自动发起。

## 操作

先导出一份每日摘要，选择其中一个工作条目的 `sourceRefs`。已有代码数值报告必须带同一要求修订。保存本地报告路径数组，例如：

```json
["before-js.json", "after-js.json", "patch-report.json"]
```

路径相对这个清单解析，清单本身不上传。只关联代码与补丁时：

```powershell
npm run contribute -- analyze-journal-task --summary diary.json --source-ref SHA256 --reports selected-reports.json --out NEW-attachment.json --enabled
```

同时关联原要求、领域表或依赖图时：

```powershell
npm run contribute -- analyze-journal-task --summary diary.json --source-ref SHA256 --task task.json --revision UUID --domain-review local-review.json --graph local-graph.json --reports selected-reports.json --out NEW-attachment.json --enabled
```

`task.json` 是既有脱敏Task；领域表、图和报告必须使用同一任务及要求修订。没有要求材料时仅保存代码数值，要求结构与难度保持未知；不从代码反推任务难度。也可以通过 `--input local-input.json` 提供完整本地输入。`schema --format journal-analysis-input` 和 `schema --format journal-analysis-attachment` 可导出机器协议，字段之外的一致性规则仍由配套程序检查。

在应用的工作条目详情点击“任务、难度与代码分析”，选择上述输入或附件。分析在Web Worker中执行，可以先检查结果，再点“保存分析为新修订”。保存不会上传，上传继续走原预览与授权。已有日记及已上传回执保留，不覆盖历史；旧日记已有新修订时拒绝向旧版本附加。

## 字段和来源

新增上传位置为 `tasks[].analysis`，版本 `journal-task-analysis-1`。它保存固定工作类型、可选要求观察、结构计数、分项要求位置、未知数量及可选 `codeMeasurements`。来源固定为 `unverified_client_program_report`，用途固定为 `private_descriptive_only`，整体难度等级为null。原要求全文、完整Task、原图、要求修订UUID、测量时间、源码、路径、原始Diff和代码内容摘要不进入这个扩展字段。

默认模型摘要仍不接受 analysis 或代码报告；生成时允许单独的 extensions 白名单，仅包含固定要求分类与最多 256 个组成部分的结构数值。程序固定标注 local_model 与 retrospective，再生成私人描述附件；关闭扩展时该通道也关闭。额外原文、源码、路径、理由文本、来源认证声明等字段全部拒绝。程序生成或用户选择的数值附件使用单独通道，经严格字段、任务来源集合、工作类型和版本校验后保存。结构一致性与摘要校验不认证客户端最初的声明真实，公共榜单仍不使用这些扩展字段。

私人反馈增加分析条目覆盖、图计算覆盖、要求已知/缺项数量，并复用已有按语言、方法、阶段、范围分组的代码与补丁分析。网页和应用共用反馈组件。工作条目、代码文件、函数、修改行和验收目标分别计量，不能相加成总工作量。

## 容量与性能

- 单份分析输入最多1 MiB；每任务附加数值最多64 KiB，每份日记全部分析最多192 KiB、64份代码/补丁报告。
- 工作线程一次只处理一个输入，不排队；面板关闭或切换任务会终止旧线程。最多缓存4份完全相同输入的投影结果，仅在内存中保留数值，不保存输入正文。
- 桌面大日记采用异步gzip level 1，无损压缩收益不足10%时保留原文；最多同时两项压缩，忙碌时不排队。服务端采用相同格式，压缩在写事务前执行。各端兼容原TEXT，压缩块检查长度、SHA-256和最大解压长度。
- 服务端容量、分页和历史读取预算仍按原始JSON字节计算，不能用压缩绕过接收限制。旧记录不批量改写或删除。
- 桌面为新分析修订保存小型列表摘要。日记列表不读取分析正文，打开具体条目时才读取详情；最新修订查询使用原索引。正文与列表摘要在同一事务保存，取消或退出时遵守现有操作等待流程。

新压缩格式和扩展字段需要配套新应用/后端，旧程序不能读取新记录。原发布应用未替换；测试使用独立数据库。新版升级和回退应保留完整备份，不能把旧EXE直接指向已写入新格式的测试数据库。

## 本机对照

32份构造日记，每份8条工作、附加相同结构的数值报告。SQLite完成检查点后，TEXT基线数据库2,326,528字节，新库360,448字节，包含列表摘要表；正文2,162,144→118,422字节，额外列表摘要82,144字节。没有VACUUM或删除历史。

四对AB/BA、每路径40次列表读取，原完整正文解析后去掉分析与新小型摘要的输出相同，中位耗时64.96→1.23 ms。另对8个文件、每文件64个函数、仅1文件内容改变作四对交替比较：全部冷解析12.29 ms，同一进程复用已有7份数值后2.80 ms，完整数值相同。复用前填充缓存的耗时未计入第二次分析，两条路径的源码均已在内存，因此不是完整磁盘采集耗时。

这些是本机固定构造数据和缓存磁盘的对照，不代表生产吞吐、网络速度、所有项目收益或内存峰值。精确样本位于 `.local/goal-progress/journal-analysis-benchmark-20261016.json`，脚本 `scripts/benchmark-journal-analysis.mjs`。
