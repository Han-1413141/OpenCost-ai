# 从本地监控历史导出额度观察

日期：2026-10-15。格式 `opencost-monitor-history-export-1`。对应 Q-07 的监控库只读导出，以及 D/U 的本地预览与有界读取部分。

## 直接使用

```text
npm run monitor -- export-observations --db selected-monitor.sqlite --subscription-ref UUID --out NEW-history.json --enabled
```

默认选最近 3 天，可以用 `--range 1d|3d|7d|30d|90d` 改变范围；或使用 `--since ISO --through ISO` 指定起止时刻。显式起点与 `--range` 不能同时使用。没有自动增量、后台启动或上传；导出不改变已有监控授权和成功上传位置。最长范围复用当前采集协议的 90 天上限。

`NEW-history.json` 可以直接放入网页或应用的本地额度面板。文件包含完整选定观察和导出概览；原始观测导入格式还可通过 `--observations-out NEW-observations.json` 另存。所有输出只写新路径，原文件保留。

没有 `--enabled` 时，不读取数据库、订阅参数、映射、配置或身份，仅生成关闭状态的报告。显式启用只授权本次所选数据库和范围的读取，不代表授权上传或启动监控。现有定时和自动功能默认值没有改变。

## 请求映射仍须有真实依据

监控快照通常能记录额度和部分流水，但不能自动证明请求到达、完整请求集合、跨池关系、同刻顺序、额度批次或全部共享消费。导出只保留这些事实，不用余额差、百分比变化或观察次数生成请求、任务量和模型成绩。

已有独立映射时，可以附带：

```text
npm run monitor -- export-observations --db selected-monitor.sqlite --subscription-ref UUID --since START_ISO --through END_ISO --mapping selected-mapping.json --out NEW-history.json --enabled
npm run monitor -- schema --format history-export --out NEW-schema.json
```

`--mapping` 文件是原 `quota-observation-import-1` 的 `mapping` 对象，包含明确规则、期初/期末状态、请求和事件对应。没有映射时，导出仍可完成存储范围读取，面板会显示“缺少映射”，不能点击运行完整回放。有映射时，原转换器继续核对覆盖、源事件、数量与末状态；检查通过后只将转换文本交给计算步骤，不再次打开数据库。

这里的范围按 `observedAt` 选择观察，包含起止两端。某份观察内部的账期、流水或初始信息可能早于起点，保留原记录才能核对历史，不能将这些内容剪掉后仍声称源流水完整。界面与报告说明这一范围含义。

## 读取与一致性

导出器直接使用 `DatabaseSync({readOnly:true})` 打开选定普通文件，并设置只读查询和关闭可信 Schema。它不经过会迁移数据库、补时间索引、初始化本地盐值的 `MonitorStore` 构造器。文件不存在时失败，不新建库；缺少支持的表或索引时返回结构不支持，不自动修复旧库。

一次操作在单个读事务中完成，并保存该读视图的最大本地序号。序号不是请求顺序或供应商事件时间。读取仅涉及观察与正文表，不读取 settings、来源配置、授权、待上传批次、密钥、上传回执或审计正文。

范围查询强制使用 `(subscription_ref,at_ms,sequence)` 索引，正文按摘要主键定位。先取最多 1,025 条元数据，判断是否超过 1,024 份观察；先累计字节数，再读取正文。相同正文按摘要缓存，只读取、解析和核对一次，所有观察 ID 与原始时间仍分别保留，不合并成一次观察。

字节预检使用 [SQLite `octet_length` 官方定义](https://www.sqlite.org/lang_corefunc.html#octet_length)：对列值可直接依据元数据取得字节数，避免为计数读取整个大字段。当前要求 UTF-8 存储；其他编码返回不支持，不在原库转码。本机 Node 24.19.0 的 SQLite 3.53.3 已核对函数可用。

每份取出的正文需与原存储的 canonical SHA-256 一致，时间索引需与原时间一致，重建的观察需通过原订阅协议。发现同毫秒多份观察或有效精度高于毫秒时停止，不按插入序号猜测先后；该订阅存在未索引时间记录时，也不能声称所选范围读全。这里核对本机记录内部一致性，无密钥摘要不证明供应商真实性，也不防止能重写整个本地数据库的管理员伪造事实。

SQLite 只读连接可读取已提交的 WAL 数据。本轮没有用 `immutable` 跳过日志，没有执行 checkpoint、VACUUM、迁移或历史更新。按 [SQLite WAL 官方说明](https://www.sqlite.org/wal.html#read_only_databases)，只读 WAL 连接可能使用或创建协调用的 `-shm` 文件，因此这里的只读是指不改变持久事实，不宣称所有辅助文件字节都保持不变。合成 WAL 用例中，主文件和 WAL 摘要、历史与授权内容保持一致。

数据库锁等待设置为每次最多 250 毫秒，不代表整个操作的耗时上限。忙碌单列原因，不冒充数据损坏，也不安排自动重试。该过程没有轮询、网络请求、账号查询、模型调用或上传。

## 容量与状态

本地观测导入上限由原 256 份调整为 **1,024 份**，文件仍最多 **2 MiB**，同时检查最终带缩进 JSON 的实际字节数。默认每 5 分钟记录一次，3 天包含两端共 865 份观察；已用该情景验证保留全部时间和数据。多池、大流水或更高频记录仍可能先达到字节上限，程序会提示缩小范围，不截断后提供完整结果。

原转换器的 8,000 个窗口内唯一源事件、16,000 个源引用、100 项诊断及回放资源边界保持不变。完整流水的区间端点预先解析，避免每次事件比较重复解析时间；诊断达到容量后立即结束，不继续做完整性结论。

| 状态 | 含义 | 是否带可交给转换器的原观察 |
| --- | --- | --- |
| disabled | 未启用，未读取源 | 否 |
| complete | 已读完该读事务内所选存储范围 | 是；映射仍可能缺失 |
| empty | 所选范围没有存储观察 | 否；不表示真实零消费 |
| incomplete | 缺索引、未索引记录或选择条件不成立 | 否 |
| conflict | 时间、摘要、正文或结构不一致 | 否 |
| capacity | 行数、正文或完整输出超过容量 | 否，不给部分观察前缀 |
| unavailable | 文件不可读或数据库忙碌 | 否 |

超过观察数时只报告已发现数量的下界，不对整个数据库执行 COUNT。失败报告不包含原正文、文件路径、供应商异常、授权和账户信息。CLI 的失败状态返回非零退出码；完整、空范围和未启用返回 0。

## 界面与已验证范围

网页和应用继续共享默认关闭的本地额度面板。导入导出报告后，先显示观察范围、数量、存储缺口和范围说明，再显示原观测映射核对。Worker 不把原观察复制回界面结果；只有核对通过才返回可运行转换文本。换文件、取消和关闭沿用原清空和终止机制。

本轮 69 项不同相关用例通过，25 项新增、44 项受影响回归，重复不计数。包括已提交 WAL、两端范围、其他订阅排除、原库保留、摘要和时间冲突、缺索引、忙碌、数量/字节容量、865 份默认范围，以及 CLI、实际打包 Worker 和静态界面。构建和交付目录记录在 `docs/status.md`。

只使用隔离临时数据库与合成观察；没有读取用户真实数据库。真实 GUI 和新机器安装尚未验收。这个入口未实现定时自动导出、跨文件连续分页、所有供应商规则适配或请求历史自动补录；不能将“存储范围完整”当作真实账号活动完整。
