# OpenCost 分析与推荐方法

版本：analysis-methodology-3，2026-10-14。本文说明当前源码实现。默认不开启难度分级、扩展采集或自动上传；统计不调用大模型。研究建议与尚未部署的方法见 [研究索引](research/analysis-20261013/README.md)。

## 1. 先确定比较的对象

一个根目标对应一项可独立验收的要求。重试、会话、模型请求、文件和所有层级子代理都不是新增成功任务。原要求、非重复组成、完成工作量、执行资源、验收质量和经验难度分开保存。混合目标的组成未知时不进入模型或套餐排名；不同成果单位不相加。

模型以供应商、型号、版本识别，配置还包括 Harness 型号、版本、变体、模式和工具设置。比较同时匹配任务类型、细类、规模、输入材料、环境背景、验收及要求条件；费用还匹配月份、币种、付费类型和归属方式。条件相同只表示记录字段相同，不能证明两个真实任务完全等价。

一项目标由多个 Harness 完成时，公开配置增加 `harnessComposition`，保存去重、排序后的全部参与产品标识、版本、型号和运行环境。主 Harness 相同但参与名单不同的配置分别汇总、分别检查发布样本门槛，不用一个 `mixed` 标签合并成本。顺序不改变身份，未知字段不补成已知版本。这个名单描述参与集合，不证明调用顺序、路由方式、各参与者设置相同，也不能把整套配置的效果或费用拆给某一个 Harness。

单模型最低成本 Harness 榜继续排除混合或归属不明的配置。套餐可以保留多 Harness 协作，但须有完整结构名单，并在反馈中展示全部参与者；跨月趋势和额度变化固定同一参与组合。旧聚合缺少混合参与名单时不参与新的排名、趋势或私人参照，不从主 Harness 名称猜测补齐。原始上传和冻结反馈保留，公开派生事实按 `public-facts-9` 分批重建；榜单方法版本为 `boards-10`。

模型榜、套餐榜、预算建议和私人反馈共用 `workload-comparison-1`：工作量单位、输入/输出数量档位、输入材料规模单位和档位须已知，混合任务须有明确细类组成；`other` 领域沿用原要求或获准变更的分类规则。旧响应缺字段、null、空值与 unknown 不进入这些比较，合法零档位仍可比较。缺项保留描述统计及原始历史，私人反馈列出具体缺项，不由模型补造。该门槛不证明任务难度相同，也不调整完成率或成本公式。采用依据见[三份 Pro 资料对照](research/pro-reference-adoption-20261014.md)。

同一上传者、同一根任务 UUID 在两个不同的完整结算中出现时，涉及整条记录的费用、验收数、样本数和套餐周期均退出比较。候选先按公开同意、完整连续范围、结束状态、生命周期费用和完整分摊确定，再一次性识别冲突，最后应用证据与视图筛选；不能循环删除后恢复另一条记录。进行中、部分费用历史加唯一最终完整结算不构成该冲突。社区总任务数仍按根任务去重，原始记录不删除，冻结反馈不重算。索引在写入时按根任务维护，请求时使用已保存的冲突数，不扫描所有上传载荷。

这项规则不能证明唯一最终结算已经包含全部历史费用，也不能识别被重新生成 UUID 的重复任务、不同任务 UUID 之间重复分摊的账期费用。没有替代链和快照/增量声明时，不把两笔费用相加或擅自选一笔；被排除的记录不代表零成本、零成果或失败。

私人贡献反馈以本记录的接收时间为历史截止，检查包含本人的私人完整结算，使用独立的有界增量索引，不受公开同意和最近 30 天采集覆盖限制。重复、待检查或无法确认时保留本次描述统计，停止比较和推荐；等待外部参照期间发生本人历史变更时不冻结结果。`lifecycle.scope` 区分服务器已接收历史和本地函数提供的有限历史，旧冻结报告保留并提示未执行此检查。具体读取预算与状态见 [私人反馈](personal-feedback.md)。

## 2. 成本与排名

新增 `allocation=itemized` 和 `cost-attribution-1`：独有费用直接归属，共享费用只在声明的目标间分配，差额保留为未归属。相同规则的费用先合并再做整数分配，任务成本与未归属合计等于账期净额；旧整池分摊保持原算法。完整明细须覆盖每个目标（包括已知零费用），部分明细即使差额为零也不进入成本比较。任务组和排名同时固定归属版本、该目标涉及的规则及整期规则，不把均摊和 Token 分摊混合。套餐沿用整期同条件要求，异构归属周期保留任务级分析，不推定为完整可比套餐；同条件套餐仍使用整期净实付。字段及例子见 [费用标准](data-standard.md#逐项费用归属)。

设同一比较单元全部已归属净支出为 C，根目标数 N，已验收目标数 A：

- 验收单位成本为 C/A；A=0 时无单位成本，仍显示支出与失败。
- 全部根目标结束后，验收率为 A/N。失败、返工、放弃支出进入 C，不再额外乘完成率惩罚，不按完成率档位分榜。仍在做或结束情况未知时保留进度及全部费用，整条记录不进入最终比较，不能只删除未完成目标来提高结果。
- 零费用显示零成本，不产生无限性价比。实付、套餐分摊、API 等价金额、当前标价分别呈现，不跨币种求平均。
- 对每类任务、每组可比条件、每个模型，从有证据的候选 Harness 中选最低观察成本。不同任务可选不同 Harness，同时显示模型和 Harness。
- 只剩一个合格对象时展示观察值，不能宣称优胜。完全同值应并列；稳定的次级排序仅用于展示，不增加优劣差异。

跨条件主排名采用共同覆盖的**发起任务构成**：任务类型等权、类内条件等权，权重为 w_k。成本为 `Σ(w_k C_k/N_k) / Σ(w_k A_k/N_k)`；完成率为 `Σ(w_k A_k/N_k)`。每项验收的人工和经过时间，同样先加权每发起目标的时间，再除以加权完成率，且要求每个条件的该项测量完整。这样成本、完成率和时间对应同一任务构成。它不是某个用户实际任务分布或购买预算，不把未成功样本当可独立无限重试的概率试验。

`equal-task-attempt-mix-v1` 同时保留旧的 `Σ(w_k C_k/A_k)`，名称为“验收成果构成等权成本”。`sensitivity` 展示两种口径的成本、名次及是否变化；这是两个估计目标的比较，不是置信区间。主成本为零时不计算相对差异；不足两个合格对象时两种名次均为空。同值采用竞争排名（1、1、3），次级 ID 仅保证显示顺序。`support` 展示本模型已观察条件中参与共同比较的数量与比例，不称全业务覆盖率。

每组条件仍选择最低 C/A 的 Harness，满足逐任务选择规则。这不等于跨条件联合最优：两条件等权，条件 1 的 A 配置每发起费用 1、验收率 0.1（C/A=10），B 配置为 11、1（C/A=11），条件 2 为 100、1。逐条件挑 A 后标准化成本为 91.82，而换 B 后为 55.5。因此页面称“各条件最低成本配置的标准化结果”，保留两个构成视角，不宣称组合全局最优。当前个人反馈仍按工作组分别给方案，不把局部节省相加成混合任务保证。

这一实现迁移了[直接标准化的固定共同构成原则](https://www.cdc.gov/nchs/hus/sources-definitions/age-adjustment.htm)，而非使用流行病学结局或风险公式为任务成本背书。成本与验收分别呈现参考 [AI Agents That Matter](https://arxiv.org/abs/2407.01502)。本轮核验官方方法页及论文摘要；原始研究记录保留此前的读取层级。

选择最低值会产生选择偏差，参考 [Cawley 与 Talbot 的模型选择研究](https://www.jmlr.org/beta/papers/v11/cawley10a.html)。反馈保存该模型候选 Harness 数、`observed_minimum` 和 `selectionUncertainty=not_estimated`，不把最低历史值解释成未来最低费用。估价按“最终验收指定数量目标”计算；套餐按完整账期购买费用与历史周期验收量下四分位选择，不把历史工作量当套餐承诺额度。

推荐页人工投入上限默认不启用。启用后要求该项测量完整，缺测与超过上限分别解释。API 预算按历史单位成本乘目标数的点估算过滤；套餐按已有账期最大支出过滤，各自标明依据，均不表示未来支出上界。API 排除原因按固定顺序互斥计数，保留零验收、费用缺失、人工缺失和超预算的区别。没有来源范围时返回空值，不用点估算拼出零宽区间。

### 成本与完成率的取舍

`cost-completion-pareto-1` 对同一可比任务构成的合格候选做描述性支配判断：成本不更高、完成率不更低且至少一项严格更好。两项各有优势的方案都保留，完全同值互不支配，不加综合权重，不改变成本名次。方法来自 [Boyd 与 Vandenberghe《Convex Optimization》第 4.7 节](https://www.stanford.edu/~boyd/cvxbook/bv_cvxbook.pdf)的多目标 Pareto 比较。这里只比较观察值，不估计不确定性，不能证明未来优胜、统计显著性或整体质量。

模型每个任务条件的 `costMargin` 保存合格候选数、最低价并列数、下一候选成本和差额。相对差额为 `(下一候选成本−最低成本)/下一候选成本`。不足两个候选不计算；并列最低价的差额为零；下一成本也为零时相对差额为空。该价差不是置信区间。算法排序一次后扫描，时间 O(n log n)，不构造候选两两矩阵。

## 3. 公开参照与来源分布

私人反馈先排除本人记录及当前可信证据确认的同源记录，再从完整公开事实历史中选择已同意统计、所需证据合格的记录。本人只有私人记录时，有效的签名来源证明仍可用于排除其他身份上传的同源公开数据；私人任务和费用不进入社区统计。排除后重新计算样本量、来源占比、统计量和推荐资格，缓存也使用相同排除规则。

`owner-and-confirmed-sources-1` 仅使用与本人记录直接关联、且经当前签名、内容及发行方校验的来源，不通过其他身份继续扩展其余来源，不接受客户端自报来源作为归属证明。没有证明关联的其他身份仍可能存在，不能声称已识别所有同源数据。每单元至少 20 项任务、5 个来源、最大来源占比不超过 35% 是发布治理条件，不是统计显著性或准确率保证。来源标识数不证明相互独立，也不等于真人数。新报告保存排除策略版本，旧冻结报告保留原结果并说明原策略。

`source-support-1` 增加以下描述量：

| 量                     | 计算                            | 用途与限制                                              |
| ---------------------- | ------------------------------- | ------------------------------------------------------- |
| 最大来源任务占比       | max(n_s)/Σn_s                   | 识别单来源主导                                          |
| 按任务权重折算的来源数 | (Σn_s)²/Σn_s²                   | Kish 权重集中度，只说明权重是否集中，不是独立样本量     |
| 零验收来源数           | A_s=0 的来源计数                | 避免只看成功来源掩盖失败                                |
| 来源单位成本四分位     | 对 C_s/A_s 进行线性插值分位统计 | 每来源等权，仅含 A_s>0 的来源；来源间分布，不是置信区间 |

四分位使用的成功来源子集必须再次满足公开门槛。若只覆盖部分来源则标 `partial`，不满足则为 `suppressed`、数值全 null。已有来源平衡成本和来源极值在任何来源无验收时保持 null，防止删除失败来源后称“全来源均价”。

配置百分位以合格公开配置为分母：低于本人值的配置数加相同值数量的一半，再除以配置总数。至少 3 个有效配置才给参考分布。它不是全体用户排名、个人能力或未来预测。缺测配置不参与该指标比较；测量覆盖不足时只展示已观察值。

## 4. 本人可获得的分析

`report.analytics` 的 `task-insights-1` 是本次记录的描述统计，包括 45 项基础指标及有相应观察时的 14 项扩展指标。每项带单位、已知观察数、应观察数、可用的分子分母和解释。

| 分析范围     | 能回答的问题                                                 | 解释限制                                                           |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------------ |
| 根目标与状态 | 验收、部分、失败、放弃、进行中各有多少；终态覆盖多少         | 进行中不是最终失败，部分成果不冒充整目标验收                       |
| 费用分布     | 每种状态分配多少，未归属多少，单目标成本中位数、长尾与集中度 | 已归属费用加未归属份额等于净支出；非验收费用不一律称浪费           |
| 尝试与工具   | 重试、返工、工具失败及人工介入                               | 工具失败率只用调用数与失败数都已知的同一任务集合；无调用时无失败率 |
| 轮次与代理   | 用户轮次、上下文变化、完整代理范围与深度                     | 跨根共享代理按全局身份去重；重试不是独立可靠性复测                 |
| Token        | 输入输出、缓存、推理及每项验收投入                           | 缓存与推理为已有计量口径的组成，不重复加总                         |
| 时间与结构   | 经过时间、等待、已验收必需部分和整合情况                     | 模型与工具累计时间可重叠；互斥时间有完整匹配才算占比               |
| 验收与后续   | 已执行检查、关键项、7/30 天重开及延迟缺陷                    | 原验收计划与事后补录分开；删失、未观察与零事件分别保留             |

`comparisonCoverage` 按根目标说明已评估、至少有一项可比较、未评估及原因。最多处理任务量最大的 24 个工作组；其余目标单列，不谎称未匹配。比较缺失原因包括参照不可用、记录不完整、工作量未知、无同条件配置、配置过少和指标缺测。每项指标仍独立检查覆盖。

新字段可选，旧冻结反馈保持读取兼容且不会被今日算法重写。公开统计暂不可用时，本人分析仍展示；临时反馈不冻结，可手动再次读取。网页与应用使用同一反馈组件，无新增定时轮询。

### 任务结束与原因

`task.status` 保留成果状态，新增可选 `task.progress` 记录执行阶段、原因和来源。执行阶段区分 running、paused、waiting_user、waiting_external、blocked、awaiting_acceptance、ended、unknown。只有明确结束的目标可用于最终比较；部分完成不等于结束。旧 accepted/failed/abandoned 保留原有终态语义，旧 partial 的结束情况为未知，原记录不改写。

`failed` 只表示目标最终未通过，不证明模型能力不足。model_limit 只来自明确的原因记录；工具、环境、资源不足、取消和需求变化分别记录。会话结束、日界截断、单次检查失败或 Token 耗尽都不推断为根目标失败。桌面语义整理的来源固定为 model_report，不能自行填写独立验证来源。

本人反馈显示阶段数量、未结束目标已归属支出和全体结束后的验收率。3 项验收加 1 项等待时，进度快照为 75%，最终失败可以为 0，最终验收率为空。公开事实编译版本升级后复用既有有界重建机制；历史原始记录和冻结反馈保持原样。

### 额度与目标的对应关系

额度百分比与 Token 可以在同一额度观察窗口内统计。当前额度格式没有根目标与额度区间的归属映射，因此不计算“验收目标/额度百分比”。Token 数量相等或窗口时长相同都不足以证明目标归属。原始额度变化、验收数和费用仍分别保留。

## 5. 扩展摘要与隐私

`task.observations` 包含可选的 requirements、validation、followup、time 四部分。每部分保存来源、覆盖、形成时点、缺失原因，值仅用闭合枚举、计数与时长。模板默认省略，用户明确选择 `init --extended-observations` 才生成空字段。实际字段见 [采集约定](../skills/opencost-contribute/references/analysis-observations.md)。

不增加原始提示词、业务文本、源码、项目/文件名称、路径、账号、语义向量或原文哈希。哈希证明字节一致性，签名证明签发身份，它们都不能单独证明最初内容真实。源声明不提升独立核验级别；AI 提取不得冒充日志事实。封闭字段的组合仍可能增加可识别性，因此公开结果继续受来源及稀有组合门槛约束，不宣称数学意义上的零再识别风险。

从原始会话提取语义仍可能消耗本地模型额度，计入 collectionProcessing。程序复用已有结构数据做统计不新增模型调用，不扫描其他未授权来源。

## 6. 难度校准：默认关闭的本地研究

现有 16 个领域、249 个活动和领域方法要求画像继续保留，生产难度仍关闭。`difficulty-calibration-research-2` 只接收固定领域、协议、验证器、数据集版本下的公开任务锚点响应矩阵：

`P(成功 | 配置 j, 任务 i) = sigmoid(theta_j - beta_i)`

最小化二项负对数似然与 L2 正则之和，优化过程中约束配置参数均值为零。使用稳定的 softplus/sigmoid、受约束 Newton 求解、线搜索和明确收敛判据；最大 16 配置、64 锚点、1024 单元、100 次迭代，避免后台无限计算。要求关联图连通、每个任务至少两配置、每配置至少两任务且总体有成败。未收敛不返回拟合分数；全成/全败项不报告其参数。

```powershell
# 默认 disabled，不读取输入
npm run contribute -- calibrate-difficulty --input .local/public-anchors.json --out .local/calibration-disabled.json
# 用户明确选择公开锚点研究后，使用新的输出文件保留历史
npm run contribute -- calibrate-difficulty --enabled --input .local/public-anchors.json --out .local/calibration-result.json
```

输出 beta 的 logit 参数和虚拟零 theta 参考成功概率 `sigmoid(-beta)`，不是 0–100 通用难度、真实模型平均成功率或跨领域等级。训练 LogLoss/Brier 仅诊断拟合，不是预测验证。来源真实性、重复独立性、局部依赖、任务族效应、留出预测及区间均未由此模块验证。没有生产调用、自动拟合、上传或榜单权重；科学验证需要交叉试验和后续样本外评估。

第二版增加 `designDiagnostics`：对假设的模型能力 + Harness 能力 − 任务难度检查观测设计矩阵的秩。报告缺少交叉、任务分配混杂、固定单一因子、未观测配置，以及同搭配的多个设置版本。原拟合仍比较完整配置，不把其参数强行拆成模型和 Harness。结构满秩不代表精度、因果效应或预测能力已得到验证；全部成功或失败的数据也可能满秩，仍不能越过原拟合条件。来源与采用范围见[编程任务难度资料核对](research/coding-difficulty-20261014.md)。

## 9. 从脱敏要求计算复杂度

`task-complexity-research-1` 是默认关闭的本地工具。它与第 6 节的经验难度校准回答不同问题：这里计算要求和依赖结构；Rasch 原型需要多个配置在共同任务上的验收记录，估计固定参照下的相对难度。生产上传与排名仍不使用两者。

程序先验证单项 Task，提取八个封闭要求维度：需求明确程度、原始材料条件、方案构造要求、知识要求、推理与论证要求、必要方法、必须保持的约束、原有材料复用条件。只有执行前或已批准变更时登记的要求进入事前判断；事后补录、未知与缺测分别保留。知识和方案构造采用项目定义的有序要求类别；形式化证明与开放式探索是不同义务，不设定谁必然更难。方法和约束不按数量直接加分。

结构计算可使用明确选取的本地要求图。程序先按稳定的 `requirementUnitId` 合并同一原要求的多个显示部分，计算依赖边、强连通分量、凝聚图最长路径、反馈和共享状态组。循环依赖单列，不能把循环压缩后的短路径解释为任务更简单。无原图时仅展示上传摘要声明的计数，不假称完成了原图去重。图限制 256 个部分和 2048 条边，没有网络调用、后台循环或自动扫描。

细分领域的要求继续使用 16 个领域、249 个活动的逐条描述。可选本地域表绑定同一任务及要求修订 UUID，程序核对适用性、要求锚点、覆盖、冲突和证据类别，展示已知条目及缺项的可能范围。不会把领域名称、技术名称或模型耗费换算为等级，也不把缺项补成最低等级。来源类别是声明，不构成真实性证明。

同类比较采用非补偿规则：工作细类、规则版本、条件、结构及适用条目相同，而且记录完整时，一项任务所有可比要求均不低、至少一项更高，才判为“要求更高”。不同维度各有高低时保留不可比较结果，不用平均分抵消关键要求。该判断不是已经标定的成功概率、工时或费用。

模型辅助路线使用 `complexity-model-review-1`。工具生成包含白名单要求快照、逐项规则和空白答卷的本地包。模型答案必须绑定任务、要求修订和规则版本；程序重新计算，单列映射一致、未知、弃答、冲突与可选领域判断。模型不能提交一个总分覆盖程序结果。领域选级仍是模型声明，需要原要求支持，结构校验不等于语义真实性核验。

网页“计算方法与数据标准 → 复杂度研究”在用户开启后才读取所选本地文件；离开或关闭后不保存研究状态。CLI 对应 `assess-complexity`、`complexity-packet`、`review-complexity`。三个命令都默认关闭，只有 `--enabled` 才读取输入，输出只写新文件；不会调用模型、读取其他会话、修改采集授权或上传研究结果。完整用法见 [复杂度研究约定](../skills/opencost-contribute/references/complexity-assessment.md)。

本实现直接采用任务测量资料、领域规范和软件图算法；不以 `cumcm-statistics` 技能作为实施或验证依据。当前可验证的是规则和代码的一致性。真实有效性仍需独立人工依据原要求复核、同任务跨配置观察、按任务族留出验证，并分别报告领域内一致性与误差。

## 10. 代码的本地程序测量

新增默认关闭的 `measure-code`，支持 JS/TS/JSX/TSX AST 结构测量。成熟项目对照、口径与使用方法见 [代码复杂度](code-complexity.md)。该指标不替代事前任务要求或经验难度，不进入上传和生产排名。

`measure-code-set` 扩展到用户选择的多文件清单：按语言合并函数数值频数，再计算整体分布，不能平均各文件的均值或百分位。模块统计不增加每文件圈复杂度基数。测量阶段、原要求修订和范围声明单列，未测得文件保持缺项；逐文件身份检查不证明整个项目的原子快照或声明阶段。每次最多 64 条选择、每文件 1 MiB、源码读取预算 8 MiB。它仍是默认关闭的本地研究，未接入上传或评分。


历史 API 等价金额采用 `price-metering-1` 的分段复核；完整、无冲突的新计量才进入等价统计。旧数据沿用来源报告金额，缺段与冲突不以零替代。公共事实 `public-facts-9` 在既有分批重建中更新这一派生金额及额度窗口上界，原始记录与冻结反馈保留；没有增加数据库轮询。计算式及来源精度边界见 [数据标准](data-standard.md#按历史价格段保存计量数量)。实际付款与 Harness 主排名公式不变，计价改动本身不改变榜单公式；固定目标版本改动采用 `boards-10`。


## 固定任务构成与观察结果

`ranking-target-1` 保存月份、任务条件、权重及选择数据截止时间，管理员显式发布。未配置时显示临时共同范围；已配置时新增窄覆盖模型或套餐不缩减目标，不重新分配缺失权重，当前月份失去支持也不自动换月。每个任务仍独立选择其观测最低成本 Harness。目标覆盖和当前数据支持分别显示，未公开条件不重新暴露明细。目标版本与当前结果版本分别记录，详细计算及发布规则见 [榜单目标版本](ranking-targets.md)。
