# 榜单目标版本与发布

模型总榜、各任务类型榜和套餐榜分别维护目标，适用范围包含领域、币种、付费及分摊规则、付款类别、费用覆盖、评价版本和证据等级。一个范围及榜单类型同时启用一个版本，月份写入版本。更换月份必须发布新版本；当前数据不足时保留原目标并显示暂不可比较。

## 计算规则

对目标条件 s 保存权重 q_s：各任务类型等权，同类型各条件等权。模型在每个条件选择观察到的最低单位验收成本 Harness，然后分别加权每次发起支出和验收率，主成本为 `Σ(q_s × 支出_s / 发起数_s) / Σ(q_s × 验收数_s / 发起数_s)`。失败支出包含在分子，不再额外乘完成率惩罚；不按完成率划分榜单。

新增候选不修改 q_s。候选缺少任何目标条件时，整体成本与标准化完成率为未知，不排名、不补零、不重新归一化权重。`support.targetCoverage` 是已匹配条件数 / 目标条件数；`targetWeightCoverage` 是已匹配权重之和。`conditionCoverage` 是该候选已观察条件进入本次比较的比例，分母不同，不能称为全部实际工作覆盖率。条件有样本但没有成功验收时保留失败事实，不从目标中删除。

固定版本只使任务构成稳定，不使样本、选中的 Harness 或名次稳定。成本仍为本次已观察候选的最低值，尚未通过独立留出样本证明未来最优。套餐遵守相同目标规则，周期卡片为各条件原始观察值，与标准化排名分开。私人反馈和预算需求继续按自身工作条件计算，不自动套用公共榜单目标。

## 管理员工作流

以下是管理操作说明，本轮没有发布真实目标或修改运行环境。

1. 手动保存一次同一实例的 `/api/explore?source=community&evidence=all` 或 `evidence=verified` JSON 响应。只使用已过发布门槛的社区聚合数据；需要记录其来源实例。程序拒绝标为 demo、synthetic、其他规则版本或未来截止时间的快照。输入文件上限 32 MiB、各类记录 10000 条。
2. 在仓库中运行 `npx tsx scripts/ranking-targets.ts prepare public-snapshot.json candidate.json oct-2026`。输出为新文件，不覆盖已有候选。程序重新从行记录提取共同条件，不信任快照中的排名分数；至少两个候选共同覆盖才生成目标，尚无成功验收的条件仍保留。审阅范围、月份、条件、权重及来源截止时间后再发布。名称只使用小写 ASCII 字母、数字、点、横线和下划线，最多 24 字符。
3. 运行 `npx tsx scripts/ranking-targets.ts validate candidate.json`，随后 `npx tsx scripts/ranking-targets.ts publish candidate.json data/ranking-targets`。发布按适用范围替换活动版本，其余范围保留。不可变的 `<目标摘要>.json` 以及 `catalog-<集合摘要>.json` 保存历史；最后通过原子重命名更新 `active.json`。失败时原活动文件保持不变，已落盘的未激活定义可留存，不自动清理历史。发布锁防止并发覆盖；进程异常退出留下锁时，管理员确认无发布进程后再移除空锁目录。
4. 在实际部署配置中指定 `RANKING_TARGETS_FILE` 为该 `active.json` 的绝对路径，再按正常发布流程切换服务。仅在启动时读取，不监视文件、不轮询、不由用户上传接口修改。配置损坏直接阻止启动，不回退为另一目标。留空继续显示“临时共同范围，候选变化可能改变比较范围”。

候选文件中的 `publishedAt` 为准备该不可变定义的时间，实际生效取决于管理员发布并启动服务。`selectionCutoff` 是保存的公共响应更新时间，`sourceDigest` 对被采用的来源字段计算 SHA-256。哈希只能发现内容变动，不能证明快照、工作量或账单真实，也不能阻止有本地管理权限的人编造来源。真实证据资格仍来自原上传校验、来源核验与发布规则。

## 历史、输出和资源

每个目标最多 256 条条件，活动集合最多 128 个目标、4096 条条件、8 MiB。目标键只能使用当前条件字段且必须为规范 JSON；内容摘要、唯一性、范围、算法版本、截止时间和权重都要通过检查。整体历史集合也保存，旧版本文件不被覆盖。公开 API 不提供这些管理文件下载；不存在当前公开行的条件在 `strata`、`selections` 中显示 `conditions:null`，不能从管理历史重新公开条件明细。

`/api/explore` 返回 `rankingTargetsVersion` 和 `statisticsVersion`，前者标识活动目标集合，后者标识本次结果所用数据及政策。网页显示目标版本、选择截止时间、结果版本和覆盖；导出包含版本及数据更新时间。`/api/rankings?kind=...` 复用同一个任务类型目标，不临时重算交集。示例与汇报数据始终使用独立临时范围，不加载真实社区目标。

固定目标会产生“候选 × 条件”的展开。创建选择数组前，所有固定总榜、类型榜和套餐榜共用 8192 格、8 MiB 估计展开量预算；估计包含条件文本和每格配置、指标余量。这是运算及分配预检，不是序列化响应大小的精确证明。超出时返回 `capacityExceeded` 及说明，保留目标和原权重，不给截断后的名次。原有 HTTP 与事实查询限制继续生效。目标版本进入应用层缓存标识；没有新建数据库事实表、重算历史账本、后台扫描或新增轮询。
