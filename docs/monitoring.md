# 可选后台记录与每日上传

已有历史可通过 [只读导出入口](monitor-history-export.md) 生成本地额度面板可接收的文件：`npm run monitor -- export-observations --db FILE --subscription-ref UUID --out NEW.json --enabled`。默认近3天、最多1024份观察及2MiB；未显式启用时不读取源，不推进上传进度或启动后台程序。

后台读取所选额度来源，按授权每天上传已有脱敏预览，不调用模型。监控默认关闭，可选择仅本地记录、每日上传和登录时启动，完成授权后执行相应命令。

现成结构记录直接复用。从旧对话提取类别、完成量、验收和脱敏摘要，需要另行开启本地 AI 整理，并消耗模型额度。AI 定时任务按唤醒和实际调用计量；支持条件触发的宿主可先检查新增内容再唤醒。当前难度分级关闭。

## 首次说明

向用户说明：

> 可选开启额度监控，帮助查看同一套餐的总额度是否增加或减少，并区分使用、重置、赠额、到期和滚动恢复。请选择要读取的具体订阅及来源。默认每 5 分钟检查一次，每 24 小时上传一次，不调用大模型。只读取所选 API 或导出文件，不扫描浏览器账号、Cookie 或其他应用。订阅记录只对你本人可见，不会直接成为已核验公开成绩。
>
> 你可以只保存在本机，也可以开启每日上传。默认增量开启后上传上次成功采集终点到本次之间的数据；关闭后每次重新选择范围。超过 3 天未成功上传会暂停补传并提示重选，推荐近 3 天，最多近 90 天。读取现成字段不花模型额度；若让 AI 整理旧对话，范围越大，额度消耗可能越多。

随后在同一次选择中列出来源、检查频率、上传站点、时间范围、增量开关、开机启动开关和停止方式。授权不存在时不执行 `grant`、`run` 或安装脚本。开启 Skill 的自动分类不等于授权扫描所有订阅；订阅来源单独选择。

## 实际支持范围

- **本地 JSON 导出或工具结束回调**：Harness、官方 CLI 或用户选定的导出器写入 `SubscriptionSnapshotSchema`，后台按修改时间读取。原子替换完整文件，保持订阅与共享额度池 UUID 稳定，每次真实观察使用新 observationId。导出程序自身的调用费用另记到工作成本。
- **JSON API**：用户指定公开文档支持的只读 GET 地址，配置 JSON Pointer 数值映射与固定结构模板。API 原始响应只在内存中解析，未映射字段不落盘、不上传。不会执行响应中的提示词。字段缺失、类型错误、超时、跳转和过大响应均记为读取失败。
- **工作预览目录**：上传已经由 `contribute prepare` 生成的完整预览。按窗口起点、终点与批次顺序处理；复用工作采集的身份、目标站点、分享范围及增量授权。目录中只放预览文件。文件全部保留，不自动删除。后台不会自行阅读旧对话或用模型生成分类。

适用于能提供上述来源的 AI 套餐、网盘、网络、存储、计算等订阅。不同服务仍需配置或编写相应导出适配器；不支持的服务显示未接入，未公开的额度记 unknown，不能声称已能读取所有互联网套餐。没有稳定 API 的网页可由用户授权的本地工具导出，后台本身不做常驻浏览器截图或抓取登录信息。

服务商的限额也有不同语义，例如 [Anthropic 官方限额说明](https://platform.claude.com/docs/en/api/rate-limits) 区分支出上限与速率限制，速率额度可连续恢复。不能把这些额度全部按月重置余额计算。

## 配置与启动

需要 Node.js 24，在工具包目录执行：

```text
npm run monitor -- init --out .local/monitor-config.json
npm run monitor -- template --out .local/quota-template.json
npm run monitor -- schema --format snapshot --out .local/subscription-schema.json
```

模板中的 unknown/null 不是测量值。按真实来源填写公开提供商、套餐及版本、Harness 型号、版本、variant、surface、订阅周期、席位、实际价格、账期、池共享范围与额度字段；无法取得的值保留 null。账号、密钥、原始用户 ID、URL、路径和正文不能写进快照。模型与 Harness 共用一池时只记一个 poolRef，不复制成多个额度。

`monitor-config.json` 中的文件来源形状如下；占位符替换为真实本地路径和模板里已生成的随机 UUID：

```json
{
  "format": "opencost-monitor-1",
  "sources": [
    {
      "id": "chosen-subscription",
      "kind": "file",
      "path": "quota-export.json",
      "subscriptionRef": "<本地随机订阅 UUID>",
      "pollSeconds": 300,
      "resetProbe": true
    }
  ],
  "workOutbox": null,
  "collectionState": "collection-state.json"
}
```

路径相对配置文件所在目录。HTTP 来源用 kind=http、url、auth、template、mapping 代替 path/subscriptionRef；template 是完整额度模板，mapping 为 `{from:"/providerField",to:"/pools/0/remaining"}` 等字段映射。单位必须与服务商一致，不自动猜测缩放。若需要转单位、ISO 时间或从复杂账单汇总，应由本地适配器先转换并留存转换版本。总额度未披露时只映射百分比及方向，不由百分比反推总量。

auth 为 null 或 `{env:"PROVIDER_QUOTA_KEY",header:"Authorization",scheme:"Bearer",origin:"https://实际提供商域名"}`。密钥由用户配置的环境变量传入，不能写进配置、命令提示词、快照或上传内容。origin 必须与 API 完全相同，禁止跟随跳转。配置文件的来源或目标映射改变后，原授权失效，需要重新展示选择。

用户选择仅本地记录后：

```text
npm run monitor -- grant --config .local/monitor-config.json --mode local
npm run monitor -- run --config .local/monitor-config.json
```

用户选择每日上传、近 3 天、开启增量、确定目标站点后：

```text
npm run monitor -- grant --config .local/monitor-config.json --mode upload --range 3d --incremental on --endpoint <已确认站点 Origin> --identity .local/client-access.key
npm run monitor -- run --config .local/monitor-config.json --identity .local/client-access.key
```

两种方式都必须实际运行 `run`，仅 grant 不代表后台已经启动。`run --once` 只检查一次已到期的来源和上传计划，适用于宿主定时执行。可以用 `--db` 指定本地数据库；所有启动、状态和停止命令须使用同一个绝对路径。不要把数据库放进工作上传目录。

`grant` 将授权、安装标识、提示状态和授权日志一起提交，任一写入失败就整体回滚，避免命令报错但授权已部分生效。重新授权时在数据库写锁内读取最新待传批次与回执；存在结果尚未确定的批次时，必须保持相同来源、身份和站点，并选择包含全部观察时间的范围。创建独立身份文件在提交授权之前完成；授权失败可能留下未使用的身份文件，但不会因此开启监控。

重新授权会让所选来源立即到期，恢复之后的正常轮询；保留原来源状态中的快照、成功时间、缓存标识和失败次数，不改写历史观察。调整也在授权事务内，授权失败时不会留下单独变更的轮询期限。

`--incremental off` 在本次明确选择的范围完成后要求再次选择，不持续自动补传。隔了超过 3 天时，status 的 attention=choose_range；AI 下次运行重新展示 1d/3d/7d/30d/90d 选择，用用户选项重新 grant。无界面后台不会假装能弹对话框：它保留提示并暂停上传，本地轮询继续；宿主需要通知时只读 status 并向用户展示。

上传失败后保留原批次、幂等键和成功位置。SDK 保留 HTTP 状态、错误代码、`retryable` 和 `Retry-After`；服务器明确返回 `retryable:false` 时，后台停止自动上传重试，本地记录仍按原授权继续。`status` 中的 `attention=upload_paused` 与 `grant.uploadFailure` 显示暂停状态和错误代码，不保存服务返回的原始异常正文。处理容量、数据或权限问题后，重新 `grant` 可恢复；存在待传批次时仍须保留原来源、身份、站点和覆盖范围，不能用重新授权丢弃旧批次。

其他上传失败保持至少 15 分钟的重试间隔；有效 `Retry-After` 要求等待更久时，保存 `uploadFailure.notBefore` 并等待到期。秒数和 HTTP 日期共用同一解析规则，不把有效的长等待裁剪成一天。超过一天时，`nextUploadAt` 只是本地检查时刻，未到 `notBefore` 不发上传请求；重启也保留等待。无效或缺失的等待头不改变原 15 分钟下限。等待超过 3 天仍须按原规则重新选择采集范围。[HTTP 等待头定义](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)

订阅上传使用独立的 `/api/subscriptions`，不会创建虚假的工作任务，也不会把每次快照中的套餐标价重复加到费用。工作账期的 `subscriptionRef` 可以关联同一私人订阅记录；该标识不作为公开分组维度。要同时传工作，设置 workOutbox，并先按贡献 Skill 完成首次手动上传和 `preferences --automation upload`。后台仅传已准备好的、符合原授权的增量预览；缺少分类的历史需要 Skill 处理。

读取已上传的私人订阅历史也按页执行，不会一次下载全部历史：

```text
npm run monitor -- mine --endpoint <已确认站点 Origin> --identity .local/client-access.key --limit 100
npm run monitor -- mine --endpoint <已确认站点 Origin> --identity .local/client-access.key --limit 100 --before-sequence <上页 nextBeforeSequence>
```

可加 `--subscription-ref <UUID>` 限定一份订阅。`nextBeforeSequence` 为 null 才表示读完；受字节预算影响，一页可能少于 limit。原快照及其全部池变化共同计入单页 3 MiB 上限，不裁剪历史。服务端逐条按实际观察时间查找基线，超过读取预算或无法确定历史时，`historyCoverage` 会说明原因，未知消费保持 null。

## Windows 后台与登录启动

需要 PowerShell 7.4 或更新版本。用户选择后，可以用包内脚本启动隐藏进程；这不是依赖 AI 的定时提醒：

```powershell
pwsh -File scripts/Start-Monitor.ps1 -Action Start -Config .local/monitor-config.json -UserApproved
```

用户还选择登录启动时，使用相同参数把 Action 改为 Install。只登记当前用户、普通权限的登录任务，不安装系统服务、不申请管理员权限。Install 不代表当前已经运行；用 Start 立即启动，再用 status 核对进程心跳。机器关机、睡眠或用户退出期间不能采集；恢复时遵守三天重选规则，不能补造停机时的重置。

Start 在创建隐藏进程后检查最多一秒的提前退出，异常退出返回失败，并提示查询 diagnostics；检查期间没有退出也只表示启动请求已发出。Node、依赖或脚本尚未加载时可能来不及写诊断；没有诊断记录不表示启动成功，需要检查终端提示或登录任务结果。

脚本把调用位置下的相对路径转为绝对路径，登录任务保存这些绝对路径。更新和移除任务前，会检查任务所属用户、普通权限、已知 PowerShell 执行路径、执行脚本、工作目录及数据库路径；同名但不符合的任务会被拒绝，不自动覆盖。保留旧版任务名称和动作格式兼容；同一路径仅大小写不同仍能找到原任务，更新时沿用原任务名及数据库路径拼写。已有多个任务指向同一数据库时会提示先处理重复任务。查询、登记或删除失败都会报告失败，只有重新读取确认后的状态才显示成功。

安装时会保存四项有效容量预算，后续登录按这组数值启动。预算优先使用脚本参数，其次使用当前进程的环境变量，未设置的参数使用默认值。只在子进程中应用预算，不修改用户或系统环境变量。可以明确指定：

```powershell
pwsh -File scripts/Start-Monitor.ps1 -Action Install -Config .local/monitor-config.json -Database .local/monitor.sqlite -StorageMaxBytes 2147483648 -StorageReserveBytes 16777216 -StorageWalMaxBytes 67108864 -StorageDiskReserveBytes 67108864 -UserApproved
```

修改预算后，用相同数据库路径重新 Install 更新已授权的登录任务；立即启动时使用相同的容量参数。旧版任务未保存这些参数，仍使用启动时的环境变量或默认值，重新 Install 后才会保存。供应商 API 密钥不会写入任务参数；登录环境需要能读取用户已配置的密钥变量。

```text
npm run monitor -- status
npm run monitor -- stop
npm run monitor -- off
```

stop 请求停止当前进程，off 撤回后续采集和上传授权。活动期间每 2 秒检查停止文件、授权和配置；空闲最多 60 秒检查，SIGINT/SIGTERM 会立即取消等待。每次读取和提交前也复核授权，预览之后撤回授权不会继续提交。更换来源、身份、站点或重新授权会停止旧进程，按新授权重新启动。已发出的请求可能已经保存，取消不能撤销该保存。

收到并验证的成功回执仍按原站点和身份保存，不覆盖新授权；没有取得完整回执则保留原批次及幂等键。工作回执与当前上传周期的成功标记在同一事务内保存，避免异常退出留下半份状态。停止会等待活动请求和读流实际清理，之后才释放锁、清除运行标记并关闭数据库。若适配器不响应取消，继续等待，不以超时假报停止完成。

关闭授权会在同一事务内读取最新状态并修改开关，保留同时到达的回执、待传批次和成功位置。后台每次写入进度都核对本次任务最初的授权，重新读取进度不会接受用户刚换成的新授权；读取成功、失败退避和提示更新也在写锁内复核。成功位置与对应提示一起保存，写入失败不会留下互相矛盾的状态。工作采集游标仍单独保存在 `collection-state`，写入前检查当前授权，只用原站点和身份的回执恢复；两个存储之间失败时保留回执，后续按原批次重试。

停止或移除登录调度只需要数据库路径，不依赖配置、身份文件、Node 或容量设置仍然有效；配置被移动后也可执行：

```powershell
pwsh -File scripts/Start-Monitor.ps1 -Action Stop -Database .local/monitor.sqlite
pwsh -File scripts/Start-Monitor.ps1 -Action Uninstall -Database .local/monitor.sqlite -UserApproved
```

Uninstall 仍需用户选择，不删除历史或凭证，也不终止当前进程。Stop 只创建停止标记；已有普通标记不覆盖，目录或链接会报错。异常退出遗留锁时先核对 status 与实际 PID，再移除对应 `.lock`，程序不自动抢占锁。无效 JSON 输入使用固定提示，不在终端输出可能包含隐私的解析错误原文。

## 本地运行诊断

```text
npm run monitor -- diagnostics --db .local/monitor.sqlite
```

该命令只读数据库旁的 `.diagnostics.jsonl`，不打开数据库，不读取配置和身份，不创建监控状态，也不访问网络。数据库打不开或容量环境配置错误时仍可使用。常规 status 也包含同一诊断结果；无法打开数据库时直接使用 diagnostics。

每次 CLI run 追加启动、首次就绪、结束或失败事件，不随两秒的授权检查反复写入。只保存格式版本、随机 runId、PID、时间、事件类型和固定原因码。配置无法读取、授权改变、身份不可用、存储不足、锁占用和运行异常分别记录；不保存原异常、路径、URL、密钥、命令参数或来源正文。无授权或已关闭时明确记为 not_authorized，并返回失败，不再静默表示启动成功。

`latestAttempt` 表示已读取范围内的最近启动尝试，`lastReadyRun` 表示最近有完整就绪事件的运行；结束事件按 runId 配对。一次失败重启不会把原来的就绪运行改写成失败。`checkedAt` 为本次查询时间，`processPresence` 只表示这次查询对 PID 的存在检查：absent 为进程不存在，present-unverified 为进程存在但身份未经确认，unknown 为未检查或无法确认。结束事件不再探测 PID。PID 可能被复用，缺少结束事件也可能来自强制退出或日志写入失败，因此这些字段不能证明监控仍在正常运行。

诊断仅在本机保存，不随摘要上传，也不作为防作弊或计费证据。单条最多 1 KiB，只读末尾最多 64 KiB；尾部查询会标记覆盖范围、坏行及不完整末行，不回显坏行原文。已有记录不删除，文件达到 1 MiB 时停止新增诊断；这是写前检查阈值，并发追加可能超过该值，不是文件系统硬配额。磁盘、权限、文件损坏或记录上限都可能导致事件缺失，诊断失败不改变原来的监控结果。达到上限后，先停止对应监控，再将完整诊断文件归档到用户选择的本机位置，之后新运行可创建新文件；不要截断或覆盖旧历史。

## 重置和用量计算

`capacity.total` 是明确的总额度，`used/remaining` 是当次观察，不把缺项当作零。自然周期保留时区和周期单位；滚动窗口、限速、并发、余额、储存上限分别标记。只有同提供商、套餐版本、席位、状态、单位、共享范围和窗口规则的有限总额才作增减比较。试用结束、换套餐、席位变化和赠额池到期单独解释。

- 同一确定周期的精确累计 used 从 80 到 90，期间消费为 10；两次观察都必须在同一明确的 `[周期开始, 周期结束)` 内，尚未开始或已经结束的周期不能据此计算。
- 重置后从 80 到 5，没有旧周期结束读数时，期间消费为 null；5 只是新周期累计值，不是负 75。
- 完整重置流水给出重置前 90、重置后 0，当前 5，期间消费为 `(90−80)+(5−0)=15`。多次重置逐段相加，任何边界缺失都不猜。
- 滚动恢复、退款、赠额、过期及修正不等于消费。完整且精确的 usage 事件可直接求和；部分流水出现 reset/refund/grant/expiration/correction 时禁止回退到简单差值。
- 完整且精确的累计用量流水可以按全部计数器调整分段。例如起点 used=20，退款前后为 20→10，之后重置前后为 40→0，终点 used=5，则消费为 `(20−20)+(40−10)+(5−0)=35`。调整本身不计消费；缺少调整前后读数、中间计数下降、同一时刻多次调整而无法确定顺序时保留 null。并发占用等存量计数不使用这一公式。
- remainingDelta 可正可负，含义只是余额变化。使用量永远为非负值或 null，不以余额差替代。

pool.ledger 保存 from/through、coverage、precision 和事件 eventRef/at/kind/amount/beforeUsed/afterUsed。每个事件本地随机 UUID 稳定复用，时间不能越界或重复。完整性必须有来源依据，不能由 AI 补全缺失事件。所有这些来源标签仍是客户端报告，Q0 不因字段写 provider_api/exact/resetObserved 就升级为 Q2。

## 性能、历史和完整性

### 容量保护

监控数据库默认使用 2 GiB 页容量预算，其中 16 MiB 留给迁移、保存已确认回执、撤回授权和退出清理。普通采集达到准入上限后停止新增读取和上传，不删除旧历史、不推进成功位置，也不把本地存储问题记成供应商失败。一次采集的快照、来源状态和日志在同一事务内提交；容量不足时整体回滚。尚未得到完整回执的上传保留原批次和幂等键。

WAL 写入日志的准入阈值为 64 MiB，磁盘默认保留至少 64 MiB 可用空间。状态中的 `storage` 分别显示数据库页、主文件、WAL、SHM、总文件占用、磁盘可用空间和阻断原因；旧 `databaseBytes` 字段仍只表示主文件大小。SQLite 页预算不是文件系统总配额，单次提交、备份及其他进程仍可能产生额外磁盘占用。

容量参数通过运行环境设置，单位为字节，不改变来源配置的授权摘要：

PowerShell 中临时设置的 `$env:OPENCOST_MONITOR_*` 只影响当前终端及其启动的进程。新版 Install 会把当时校验后的有效预算保存到登录任务参数；日后仅修改环境变量不会改变这组已保存的参数，需要重新 Install。直接运行 CLI 时仍读取当前环境，修改后需重启监控进程。

`npm run monitor -- storage-options` 可查看当前环境下的有效预算，不打开数据库或配置、不启动监控。也可用 `--max-bytes`、`--reserve-bytes`、`--wal-max-bytes`、`--disk-reserve-bytes` 临时覆盖并校验对应数值；该命令只输出结果，不保存设置。

| 环境变量                              | 含义               | 默认值                         |
| ------------------------------------- | ------------------ | ------------------------------ |
| `OPENCOST_MONITOR_MAX_BYTES`          | 数据库页总预算     | 2,147,483,648                  |
| `OPENCOST_MONITOR_RESERVE_BYTES`      | 数据库恢复保留空间 | 16,777,216，小预算时按比例缩小 |
| `OPENCOST_MONITOR_WAL_MAX_BYTES`      | WAL 准入阈值       | 67,108,864                     |
| `OPENCOST_MONITOR_DISK_RESERVE_BYTES` | 磁盘可用空间下限   | 67,108,864                     |

达到容量上限时，后台结束当前任务并释放运行锁，`attention.code=storage_full` 在能够写入时保留原因。磁盘无法写入时，连这个提示或运行标记也可能无法更新；以实际进程和 `storage.writesAvailable` 判断，不能只凭旧心跳认定仍在运行。先备份，再增加预算或释放其他文件占用的空间，随后用原配置重新启动。不得通过删除历史或修改已保存的消费数值恢复空间。

### 完整备份与恢复

以下命令只创建监控数据库副本，不调用模型、不上传数据、不启动监控，也不安装登录任务：

```text
npm run monitor -- backup --db .local/monitor.sqlite --out backups/monitor-backup.sqlite
npm run monitor -- restore --input backups/monitor-backup.sqlite --out .local/monitor-restored.sqlite
```

使用新的目标文件名；已有文件、源文件及 SQLite 辅助文件冲突都会拒绝覆盖。备份通过 SQLite 在线接口包含已提交 WAL 内容，检查完整性后输出文件大小和 SHA-256。命令以只读方式打开源数据库，不运行监控迁移；即使监控容量配置无效，也可以先备份旧库。降低预算不会截断原库；旧库迁移需要额外空间而无法完成时，先备份、调整容量，再重新打开。

副本包含全部额度观察、已保存的结构化快照正文、哈希链、授权、来源状态、待传批次和回执，属于私人文件，不能作为脱敏摘要上传。API 环境密钥、独立访问密钥文件、监控配置、导出目录、工作采集的 `collection-state` 及运行诊断旁文件不在 SQLite 内，需要另行保留。

恢复保留原授权内容，但不会自动启动。启用副本前，先对新路径运行 `monitor off --db .local/monitor-restored.sqlite`，核对来源、站点、身份文件和增量范围，再明确授权运行；原库和备份均继续保留。完整备份不等于异地备份，保存位置与留存数量由用户选择。

### 日常读取与历史校验

默认每源 300 秒，常规最小 60 秒，最多 20 个来源，网络串行、8 秒超时、1 MiB 响应上限。文件未变化跳过解析；HTTP 使用 ETag/Last-Modified。已知重置边界最多附加前后探测，最短间隔 30 秒；失败指数退避至最长 1 小时。普通等待最多 60 秒唤醒检查停止状态，不轮询整份历史，不启动常驻浏览器或大模型。

每个来源使用读取完成时刻安排下次轮询；没有供应商观察时间的 HTTP 响应以完整读完响应的本机时间记录，明确映射的供应商时间和文件原时间保持不变。多个来源顺序执行时分别计时，失败退避从失败完成时刻开始。新上传周期的排他终点是本次采集截止毫秒的下一毫秒，以包含已经采到的同毫秒快照；不修改观察时间，旧周期和待重试批次继续使用原终点及幂等键。

运行中本机 UTC 时间比本次运行已见时刻回拨超过 60 秒时，监控取消新操作并记录固定原因 `clock_changed`。启动时也检查授权、成功位置和待传终点是否明显在未来，以及下次轮询或上传是否超过正常最大等待期限；异常时不报告就绪。该检查只读当前配置与调度状态，不扫描历史，不修改系统时间，也不判断供应商是否作弊。正常跨日和时区变化不触发；停机或休眠超过三天仍遵守重新选择范围的规则，不补造遗漏观察。

出现该提示后，先校准设备时间，再核对 status 中的范围与待传批次，重新选择范围并执行 grant，随后启动。明确重新授权会重排所选来源的轮询期限；已有历史和回执继续保留。若旧待传批次的截止时间或记录本身仍晚于正确的当前时间，仅重新授权不能解除限制，不能篡改时间或自动删除批次绕过检查，需要先核实来源记录。少于等于 60 秒的回拨属于容忍范围，前后观察和缺失流水仍按上述计量规则处理。

本地 SQLite WAL 追加观察、状态和采集日志，重复快照正文只存一份。日期索引及分页控制读取量；每日上传最多每批 100 项并按 512 KiB 继续拆分，每次最多 64 批，保留后续待传记录。失败保留原幂等键。全部批次有回执后才推进；空扫描、部分来源失败及网络超时不能冒充成功。历史不自动清理，长期磁盘用量可在 status 查看；只关闭监控不删除记录。

观察时间与收到文件的时间分开处理。成功扫描之后才收到的旧快照，只要仍处于用户授权区间内，就按原观察时间补传；已保存回执用于去重，不会因早于上次成功位置而被跳过。早于授权起点的记录保留本地，status 的 rangeNotice 提示重新选择范围，不擅自扩大上传范围。重新选定包含该时间的范围后才具备补传授权。

本地额度变化按各额度池分别查找前次观察和同条件容量基线，不再把固定条数之外的历史当作不存在。每次 status 的计算共用 2,048 行、8 MiB 正文预算；达到预算时，未找到的部分标为 partial，已确认的前值仍可用于计算。当前快照本身无法安全读取时直接报告原因。读取前核对正文大小和留存哈希；这种核对不能证明原始填报真实，也不提升 Q0 证据等级。

本地库增加数值毫秒时间索引，按实际时间筛选和排序，原始 ISO 时间、正文、回执及哈希链保持不变。首次打开时在事务中每批处理 256 条旧时间元数据；旧版程序按原列写入的记录会在新版下次打开时补齐索引。遇到无效时间、同毫秒冲突或索引与原文不一致，不猜测前驱或重置消费。状态计算仅在请求时执行，不随每次后台轮询扫描历史。

本地按顺序保存加盐哈希链，`monitor verify` 按需检查快照与历史摘要，不在每次轮询重扫全库。上传同时保存链头，服务器拒绝已留存序号倒退和不连续链头，原快照不可覆盖。链头只能约束已提交历史；控制本机的人仍可在首次记录时伪造事实，或重写未上传历史。独立签名、费用/验收/完整范围权限与服务器门槛才决定可信排名，本机签名不能自行升级。

当前实现不携带账号、原始响应、错误正文、API URL、路径或密钥到服务端。公开产品标识须由用户核对；随机 UUID 和哈希不等于数学意义上的匿名证明。默认私人记录可保存观察时间和实际金额；公开统计仍使用独立门槛，不公开个人时间线。
