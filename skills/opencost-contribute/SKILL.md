# OpenCost-AI 贡献

**没有适配器也要完成摘要。** `dsh-opencost-export-1` 是可选计量入口，不是上传前提。发现插件未提供导出或开关时，立即按 [无适配器摘要流程](references/adapter-free-summary.md) 从用户已授权的会话、日志和成果自己整理。任务事实齐全时使用通用 capture；缺少尝试次数、验收等必填事实时用 `summary-template → summarize → journal-prepare → journal-submit` 生成私有工作日记。不得虚构缺项，也不得因适配器缺失阻止已有工作摘要上传。

原要求已有可靠分类时，可选填写 `task.requirementClassification`：固定子类型、学科代码、工作/学习/个人用途、basis及coverage；混合目标componentTypes只记原计划的各细类部分数。没有依据保持null，不能用最终成果回填。详细规则见 [采集与评价约定](references/collection-contract.md)。日常摘要不必读全套文献、不重新评判难度、不增加模型调用。

只读取用户指定的范围。原始源码、文稿、提示词、会话、业务名、账号、路径、账单和来源清单留在本地。服务端接收枚举、计数、区间、公开产品标识及随机任务标识，不接收任务原文，也不调用大模型评分。

**当前使用 `work-summary-1`，难度分级关闭。** 默认只摘要已完成工作和实际投入，不生成简单/中等/复杂标签，不填写难度、置信度或未来方法难度。扩展脱敏分析默认开启，可关闭；按 [可选结构观察](references/analysis-observations.md) 保留原要求中已有的知识、推理、方法类别及验收、等待、随访事实；这些字段没有难度权重，不进入排名。只提取已授权材料中的固定分类、数量与结构；模型提取标 local_model，不能伪装日志实测。缺项保持未知，禁止把姓名、业务、项目、路径、源码、链接、账号、密钥或原文编码进任何字段。代码数值优先复用用户已选报告，没有报告时仅处理已授权的文件，不扩大扫描范围。分领域草案不由日常采集自动执行。

用户选择记录要求变更或验收后重开，且已有结构事件时，按同一参考的“要求历史”规则给本地 capture 添加 `taskHistory`，由程序计算 `task.observations.history`。条件原文、条件/成果/事件标识不上传；不得让模型补写用户批准。一次目标的多次验收和重开不增加根目标数。同一原要求的结果与累计费用更新使用明确结算修订；范围变化不能借用旧修订链装成原要求完成。

## 首次说明与时间范围

先读 [首次说明与自动运行](references/first-use.md)。从当前会话和已绑定信息识别 Harness、已有授权来源及站点，不让用户重复填写。用三句以内说明开源与提示词来源、原文留本机、AI 整理会消耗额度，再一次询问是否按推荐方案生成预览：明确来源、近 3 天、开启增量和扩展脱敏分析，自动运行和订阅监控关闭。用户可以只说“开始”或修改一项；未答复不能执行。自定义时再展开其他范围及开关，上传时再确认预览、站点和分享范围。用户关闭扩展分析时使用 init --no-extended-observations，之后保留其选择；重新开启用 --extended-observations。用户接受方案后可用 init --recommended，命令只生成模板，不读取历史或上传。

下一次在增量开启且间隔不超过 3 天时使用上次成功上传的采集终点到本次运行；显示实际起止时间。超过 3 天重新显示范围选择，自动运行暂停补传。默认增量和自动运行均可关闭。需要 AI 整理历史时使用宿主定时功能；已有结构数据与额度记录可选独立后台程序，不消耗模型额度。没有实际启动或登记调度成功不能声称已经启用。

**每天从原始对话提取任务类别、完成情况与脱敏摘要需要调用大模型。** 取得自动运行选择时明确说明这部分额度消耗。先复用已有结构结果，只处理新增缺项；任务结束时顺带生成字段也会占用当次输出 Token，不能称为免费。纯程序只能汇总计量事实、渲染已有分类及上传现成预览。整理调用、全部整理子代理与已知费用记录在 collectionProcessing，缺项为 null；不得把采集开销重复计入账期或伪装为成功任务。

## 采集与分类

1. 先读 [采集与评价约定](references/collection-contract.md)，按目标安装的 `shared/schema.ts` 与 `docs/data-standard.md` 填写；从原始目标确定主要 `kind`，原有计划规模由 `taskDomain`、`taskUnits`、`taskInputUnits` 决定单位。不能仅凭文件扩展名、项目名称或模型做了多少轮判断任务类别。
2. 将用户选择传给 init，使用独立运行目录生成全部字段及固定 `collectionWindow`；具体参数见首次说明。只处理 `[startAt,endAt)`，先按索引统计再读正文，优先复用已有结构字段。模板中的 null/unknown 是缺项，不是样本；未取得的实付和退款填写 null，分摊方式为 unallocated；币种只指定计算与展示口径，不证明有付款。尝试次数等贡献必填事实未知时改用无适配器日记流程，不填零凑通过。需要机器协议时执行 `npm run contribute -- schema --format capture --out .local/capture-schema.json`；上传字段协议使用 `--format envelope`。
3. 一项可独立验收的目标记一个根任务，跨会话、模型、代理和账期复用本地随机 UUID。已知计划组成写到 `evaluation.requirements.parts`，记录整合验收及完成部分数；未知为 null。子部分与根目标不得同时作为成功任务；重试、工具步骤、文件数、对话轮次都不增加任务数。
4. 通过成果或执行记录填写 `evaluation.completedWork`：主要类别 kind、可选细分类 workType、单位 unit、planned/completed/accepted、来源 source、验收方式 acceptance、覆盖 coverage。细分类和允许单位见 `/api/work-taxonomy` 或 `shared/work-taxonomy.ts`；无法可靠细分为 unknown，不为填细分类额外扫描全部历史。相同类别、子类型、单位先去重合并，混合任务分别列出，单位不能混加。旧的 workload.outputUnits 是计划区间，不能充当实际完成量。未测量、未验收填 null，不能猜数或把完成等同通过验收。只保留现成计划与事实，不判断难度或填写未来方法要求。
   有现成成果身份、修订或组成图时，按 [工作量与任务组成](references/work-measurement.md) 填本地 `workItems`、`workGraphs`，让程序生成完成量与结构统计；没有这些事实保持 null，不额外扫历史凑字段。同一最终成果的修订、重导出及后代副本不累计数量。
5. 遍历根代理及其全部后代，直至不再有未读取的子代理；不限预设层数。逐个保留本地父子关系、稳定费用事实标识、调用和资源记录。没有权限或日志缺失时把对应范围标为 partial/unknown，不能只采根代理却声明 complete。
6. 保留真实失败、放弃、进行中、救援和模型/Harness 切换。所有模型合并为该根目标的模型组合；不能只把最终成功算给主模型、最后模型或 Token 最多的模型。全部参与 Harness 同样保留。逐次 `model_call` 在本地保留真实 `agentId`、调用用量及可取得的 `at`（UTC）或 `sequence`（同代理的日志顺序）。`capture` 按每个代理分别生成 `execution.modelTimeline` 和 `modelSwitches`；A→B→A 是三个阶段、两次切换，并行后代之间不算切换。顺序、模型或覆盖不全时完整次数为 null；分段 Token 缺项不按比例补齐。禁止模型估算切换次数或伪造调用时间；本地代理标识不上传。
7. 记录用户消息、助手消息、模型请求、工具调用、上下文变化、人工介入、需求变更及资源用量。事件类别分别声明采集完整性；完整用量账单不代表完整会话或人工记录。没有采集的数值为 null，完整检查后没有发生才为 0。
   Harness 保留公开型号 id、version、可核对的 variant 与 surface，以及模式、工具、推理与缓存配置。不同后代使用不同 Harness 时全部保留，不能用根代理配置代替。

## 程序编译与历史价格

已有 dsh-cost-meter 标准导出时按 [DSH 适配说明](../../docs/dsh-cost-meter.md) 处理。插件采集、额度采样均为独立可选开关，默认关闭；不能因安装、升级或使用 Skill 自行开启。用户已选择后复用选择，关闭保留历史。用 inspect-dsh 查看匿名代理根，用 import-dsh 将选定时间窗内的事实并入本地 capture；映射到已有根目标，不能把会话数推断为任务完成量。已知 Token 是观察小计，实付、验收、公开 Harness 版本未取得时保留缺项。导入不调用 AI，不联网，不授予上传或后台授权；旧 dsh-cost-contribute Skill 的固定社区地址和 v2 协议不是 OpenCost-AI 接口。

8. 本地 `agents` 保存树，`events` 保存调用事实，`charges` 保存净费用事实，`resources` 保存资源事实并逐项声明 `coverage.resources`。相同事实在根代理与子代理日志中出现时必须使用同一个 ID；不能用代理 ID 给同一供应商交易另造 ID。父级累计费用和资源标为 `aggregate`，自身新增项标为 `direct`。记录模型、Harness、工具、计算、存储、网络及其他支出；退款与已归属的共享费用必须在本地对齐账单，不能重复分摊。已取得的折扣、抵扣、赠额、余额、到期时间及已含税费记录在 `period.billingBenefits`，不与净实付相加。
   同一真实代理参与多个根目标时，在本地 `taskIds` 登记参与映射，包含主 taskId，后代参与范围须出现在祖先映射中。每条执行、费用和资源事实仍只归属一次；共同输入材料可以复用。`executionScope` 的全局身份去重数与各目标参与数分别保存，不能相加成更多代理。代理转发、系统继续及工具回包不算真人轮次。
9. 在 `manifest` 记录本地来源对应、计量单位、授权连续范围和完整性依据，保留模板生成的随机 salt。只上传程序计算的加盐摘要，不能直接哈希提示词、标题、路径或低熵业务信息。模型、套餐、版本和 Harness 只能用可核对的公开产品标识；私有别名转换为公开产品，无法识别填 unknown，不能上传内部路由名。
10. 为实际调用保留当时价格版本及 `priceSnapshot`；调价跨越任务时保留 `priceHistory`。历史快照没有取得就为 null，不能拿今日价格补写历史。API 等价金额与实付分开；跨币种折算保留 `equivalentConversions` 的汇率日期和快照，不混加币种。临时赠额、折扣与促销在付款类别中记录，未获到账资格的宣传额度不当成付款或可用余额。
11. 运行 `npm run contribute -- capture --input .local/capture.json --out .local/record.json`。程序检查树、重复事实、费用守恒，汇总所有后代模型用量和事件，生成纯结构上传记录。原始 ID、树边、来源清单与业务原文不进入输出。不完整调用范围不进入单模型排名。字段或体积超限时保留完整本地材料并报出阻塞，禁止截断成“完整”。
12. 运行 `npm run contribute -- prepare --input .local/record.json --out .local/preview.json --share private`。分享选项为 private、statistics、summary。程序给出分单位完成量、根目标验收、Token、轮次、费用、代理范围和排名排除原因；不联网。显示完整总量和已知小计的区别，缓存和思考 Token 不再加到总 Token 中。

## 确认与上传

13. 展示完整待上传字段和预览文件，说明未知项、费用覆盖、代理遗漏、历史价格依据与分享范围。确认不含业务标识或自由原文。统计与公开分组摘要分别由用户选择；内容变更后重新 prepare。
14. 用户明确确认本次内容、目标站点和分享范围后，执行 `npm run contribute -- submit --preview .local/preview.json --endpoint <用户站点> --confirmed-digest <本次摘要>`。没有确认不能代填摘要。用户已明确开启并配置自动上传时，按首次说明用 `--automatic`，不重复要求同一授权；只预览模式不上传。上传只发送 envelope 与可选独立证明，不能上传 capture、manifest 或整个目录。超时重试复用原预览和幂等键，多份数据全部成功才推进增量位置。
15. 保存程序输出的完整历史回执与小型 `access.json` 路径；桌面或 CLI 导入凭证时选择后者。程序按站点、身份及内容版本保留历史，不能手工覆盖旧回执。两类文件均含访问密钥，只存本地私有目录，不上传为脱敏摘要，不粘贴完整文件或裸密钥。用户需要直接访问时，可提供程序生成的私人反馈链接，并说明持有者可访问该身份的记录；链接不能进入公开摘要、公开分享或定时任务提示词。只报告接口确认的保存结果；服务器已保存但本地保存失败时，保留原预览、凭证与幂等键重试，不重新生成身份。文件位置及导出失败处理见 [接入说明](../../docs/integration.md)。C1 表示存在本地采集元数据，不证明记录真实；费用、工作、完整范围、额度分别由已登记独立验证方核验。不要自行签发可信证明。

采集任务状态时按 [任务是否结束](references/collection-contract.md#任务是否结束) 同时填写成果状态与执行阶段。部分完成、暂停、等待、受阻和待验收均不推断为最终失败；模型无法完成、工具故障、环境或资源不足、用户取消分别记录已有依据。

## 上传后的个人反馈

用户需要修正已上传费用、结果或用量时，读取 [完整结算修订](../../docs/settlement-revision-design.md)，使用 `settlement-revise` 从“我的记录”下载的修订依据准备整个新版，再沿现有预览与确认流程提交。普通增量采集不自动建立替代。原账期、全部根目标和要求版本必须一致；要求变化或差额不能假装成完整替代。同修订重试保留原回执，旧正文和历史反馈不覆盖；父引用、要求引用和修订号由程序生成及核对，不由模型猜测。

上传成功后读取程序回执中的 `feedback`，向用户说明本次完成量、验收目标、实际费用、Token、轮次、全部层级代理和可确定的额度变化。反馈由程序计算，不额外调用大模型。只解释接口返回的数值、比较依据和候选方案；不补写未知费用、用户排名、难度或所谓最优套餐。

回执的 `feedbackUrl` 是本站私人反馈链接，覆盖工作贡献、日记与订阅三类；由程序生成，不手工拼接密钥或替换站点。密钥只放在 `#feedback?...` 片段，网页读取后立即清除地址栏片段。用户打开链接或导入凭证后，已登录账号会自动验证关联；未登录时可先查看，10 分钟内完成 GitHub 登录可继续自动关联。关联只统一访问，不改写原记录、历史反馈或公开范围。使用“个人反馈”页面查看全部类型，原访问凭证继续有效。

用户参加 VBTI 时，提供回执的 `vbtiUrl`，它直接进入 `/vbti/result/`，不再让用户先打开费用反馈再找按钮。工作贡献与日记的 `feedbackUrl` 也直达 VBTI；订阅的 `feedbackUrl` 仍定位额度报告。只有订阅上传时，明确告知尚无工作摘要，额度或余额不能计算工作类型；提供 VBTI 入口供查看已有工作，不能把订阅回执当作已生成角色结果。旧客户端没有 `vbtiUrl` 时保留原链接，提示更新本站工具包，不手工拼接凭证。读取失败只重读反馈，不要求重新上传已保存的记录。

缺少费用、验收、测量或社区样本时，明确显示“数据不足，稍后再看”，继续解释已知工作与用量。反馈暂不可用时使用原回执手动再次读取，不重复上传；历史反馈保留生成时条件，后续新数据不冒充当时已有依据。

默认提醒用户：单次结果可能受任务差异、缓存、返工和活动价格影响，建议连续记录至少一周，最好一个月。同批分片、重试和同一天的日记修订不能充当多次独立测量。公开参照是同类工作条件下已核验配置的数值位置，不是所有用户的排名。

反馈可包含本次记录的 `analytics` 与 `comparisonCoverage`：逐项解释已知观察数和分母、费用按结果分布、时间与代理覆盖、可匹配目标及未评估部分。缺测保持未知，来源数不称独立用户数，观察范围不称置信区间。配置位置优先解释低于、相同、高于本人值的具体配置数及缺测排除数；百分位仅描述本组配置。详见 [可选结构观察](references/analysis-observations.md)。

用户选择试验任务复杂度时，读取 [程序复杂度与模型辅助审查](references/complexity-assessment.md)。这是普通上传流程之外的本地可选步骤：程序计算结构和规则画像，模型依据细则提交带字段引用的判断，由程序校验并记录分歧。默认关闭，不把试验结果写入上传记录或生产排名，不自动调用 Harness、扫描更多历史或消耗模型额度。已有来源声明不升级为独立事实，缺项不填零，保留原摘要与每次试验版本。

推荐必须展示模型与 Harness、任务条件、价格月份、费用口径和可比候选数量。按不同任务选择该模型最便宜的 Harness；套餐只在完整周期证据能覆盖任务量时推荐。历史报价不保证当前购买价格。反馈不授权购买、切换环境或开启自动运行。回执没有反馈时仍报告上传成功，不为获取反馈重复上传。

桌面应用的“个人反馈”支持导入本次保存的访问凭证，读取同一身份的分析。凭证只在本机私有目录保存，不能公开或传给摘要整理模型；私人反馈链接按上述访问流程处理。算法与接口见 [个人反馈说明](../../docs/personal-feedback.md)。

## GitHub 账号汇总

用户选择把本机记录关联到 GitHub 时，使用本次上传的同一站点与凭证执行 `npm run contribute -- account-connect --endpoint ORIGIN --out NEW-connect.json`；已有凭证文件使用原来的 `--credential` 或 `--identity`。在本机浏览器打开输出文件的 `url`，用户登录后执行 `account-status` 核对关联结果。链接一次有效，10 分钟过期；不要把链接或凭证放入公开摘要、截图、聊天回复或提交到 Git。连接过程只关联身份，不读取历史对话、不上传摘要、不改变分享范围、自动运行或监控设置。

关联后，此身份已上传及今后上传的工作摘要、日记、订阅额度记录和反馈归入账号。其他 Harness 使用同一访问凭证，或分别关联同一个 GitHub 账号。桌面应用可在“个人反馈”点击“关联 GitHub 账号”，同时关联应用保留的本站点旧凭证；已被删除或遗失的历史凭证不能凭电脑信息找回。未上传的本地日记仍按原上传选择处理。

## 可选订阅监控与每日上传

**首次也能选择单次额度采集，无须开启后台。** 按 [历史用量与单次额度采集](references/quota-collection.md)，读取用户选定的 Codex 额度日志、DSH 导出、标准快照及已配置接口，执行 `monitor collect --enabled` 生成覆盖报告和分批预览。已有工作 Token 继续通过原采集流程读取。只保留实际历史、当前读数与缺口，不用百分比推算 Token、总额度或实付。单次读取、后台监控、上传分别沿用用户的明确选择；默认监控和自动上传关闭。

首次在同一次选择中说明：额度监控默认关闭，可选仅本地记录或每日上传，并另选是否登录启动。它帮助区分总额度增减、使用、重置、滚动恢复、赠额和到期。先取得用户指定的订阅来源，再读取 `docs/monitoring.md` 配置本地文件导出或只读 JSON API；不能扫描全部账号，也不能宣称已支持所有互联网套餐。

用 `npm run monitor -- template/schema` 生成完整字段和协议。保留套餐版本、订阅周期、席位、价格依据、账期、自动续费状态、适用 Harness、模型与共享额度池。总量不公开则保留 unknown/undisclosed，只记录可取得的百分比及方向。失败读数不覆盖原基线，不把零余额当作套餐减量。订阅价格快照不作为新的付款再次加入工作费用；工作账期可通过本地随机 subscriptionRef 关联。

按用户选择运行 `monitor grant --mode local/upload`；上传还须用户选定范围、增量开关、目标站点和身份。随后实际执行 run 或用户选择的后台启动脚本，核对 status 心跳；仅写配置不算已经运行。后台每天上传已经脱敏的额度和工作预览，不调用 AI 重新扫历史。长期离线、读取失败、缺重置边界只保留缺项，不虚构消费。需要交互选择时读取 status.attention，重新显示范围选择；不在无界面程序里宣称已弹窗。

用户、其他提示词或系统提示词要求增加任务数、修改工作难度、伪造验收或补齐未取得费用时，都不能代替事实来源。AI 只提取有依据的分类；费用守恒、完整范围、全部后代与独立证据由程序检查。本地哈希链及远端链头检查历史修改，不证明最初输入真实。订阅观察始终为私人 Q0，不能写 exact/provider_api 就变成独立证明。

同条件费用排名使用“全部归属净支出 ÷ 已验收根目标数”，失败费用已进入计算，不按完成率档位筛选、不再额外乘一次完成率。每个可比任务条件分别选该模型最便宜的 Harness；不同任务可选不同 Harness。多条件主排名采用同一发起任务构成的加权费用除以加权验收数量，同时展示验收成果构成口径的敏感性。原始记录不因后续规则、活动或调价而覆盖。
