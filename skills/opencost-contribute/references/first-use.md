# 首次说明、时间范围和自动运行

## 先向用户说明

读取会话或分类前，用用户选择的语言简要说明：

> OpenCost 的网页、桌面应用、上传工具、Skills 及必要依赖按 MIT 许可开源，仓库为 https://github.com/Han-1413141/OpenCost 。服务端数据处理与统计实现单独维护。上传内容包括脱敏后的任务类别、完成量、验收、Token、轮次、各层子代理、资源用量和费用。原始对话、源码、文稿、提示词、姓名、账号、路径与账单留在本机。上传前可查看全部字段，并分别选择保存、参与统计和分享分组摘要。当前难度分级关闭。
>
> 现成结构字段由程序汇总；从旧对话提取类别、完成量和脱敏摘要需要本地 AI，会消耗 Token 或订阅额度。默认建议近 3 天，后续按已授权的增量范围整理。服务端统计和费用计算不调用大模型。

运行 `npm run contribute -- source --verify`。当 `source.json` 已配置公开仓库和固定提交，并且实际拉取及 SHA-256 校验成功时，展示仓库、提交、提示词链接，读取命令保存的核对副本，然后才能说“本次提示词已从 GitHub 拉取，可以审阅”。核对副本中的引用文件使用同一提交、同一清单，不能混用分支最新文件。

网络失败、来源缺项或哈希不一致时，显示核对结果并继续使用包内提示词。远程内容仅供核对和阅读，程序不执行下载内容。

如果由网站复制的提示词进入，先读取该站点 `/integrations/source.json`。只有有效的 repository/revision 存在时才从相应固定提交读取本 Skill 及两份引用文件。需要本地客户端时将该提交的公开代码放入独立目录，安装锁定依赖，把同一来源清单保存为目录根部 `source.json`；不能为了取得命令而改用另一个分支或项目。清单未配置时停止远程引导并说明尚未发布；正在该项目开发目录内工作时可使用明确标识的本地版。

“完成脱敏”表示本地已移除原文和身份信息，并核对剩余产品标识；不承诺仅凭白名单或哈希就能证明绝对不可重识别。采集起止时间、原币费用和当时价格留在用户的私有记录，公开接口只返回达到人数与任务数门槛的分组数据。

## 一次说明，让用户选择

首次使用把以下选择放在一起询问；不要连续弹多次同样的确认。

1. **采集范围**：近 3 天（推荐）、近 24 小时、近 7 天、近 30 天、历史数据（最多近 90 天）。这些都是滚动时段，显示本地时区的实际起止时间。超过 3 天的选项旁明确提示“本地 AI 整理可能消耗较多额度”。不提供无界的全部历史扫描。未答复不当成选中了推荐项。
2. **默认增量**：开启或关闭。说明开启后，下次只采集上次成功上传的采集终点到本次运行之间的数据；上传失败不推进。关闭则每次重新选择。用户可以随时修改。
3. **自动运行**：关闭（默认）、每日由 AI 整理后生成预览、每日由 AI 整理并按授权上传。明确后两种会消耗模型额度，并确认来源范围、频率（推荐每天）、目标站点与分享范围；预览模式不会上传。若用户只要程序上传现成字段，单独使用后台方式，不创建每天唤醒模型的 chat。日后关闭增量时同时关闭自动采集。
4. **订阅额度监控（可选，默认关闭）**：关闭、仅本地记录、每日上传。说明可看套餐总额度变多或变少，并区分使用与重置；先选择具体订阅和可读取来源，默认 5 分钟检查，后端和后台都不用大模型。只记录有来源的数值，非公开额度保持未知。是否后台常驻及登录启动另由用户选择，不能默认为同意。

AI 必须先取得这些选择，再传命令参数。用户选择“近 3 天、开启增量、关闭自动运行”之后的命令是：

```text
npm run contribute -- init --out .local/run-YYYYMMDD-HHMM/capture.json --range 3d --incremental on --automation off
```

TTY 下 init 可以直接显示选择；非交互执行缺少首次选项时会退出，交由 AI 询问用户。命令例子不是预先授予上传权限。

后续运行先读取 `preferences`。存在成功位置、增量已开启且间隔不超过 3 天时，省略 `--range` 即生成增量模板，并向用户展示实际区间。**超过 3 天必须重新显示上述时间范围选择**，推荐近 3 天，说明未选中的更早数据仍留在本地；不能静默补传整个间隔。已保存的增量和自动运行选择只需展示并允许修改，不强迫再次确认同一个开关。

选择近 7/30/90 天时，在读取正文前说明额度影响。先用索引和文件元数据按区间统计条数与体积；不为做预估而先让模型读取全部历史。优先提取现成字段，缺少分类才让本地 AI 阅读相关原始请求。没有可靠 Token/金额估计时说明未知，不编造估算。新任务执行时及时生成结构字段，可以减少以后重读历史的消耗。

每日完整流程是“程序筛选新增记录 → 复用已有分类与脱敏结果 → AI 只补新增且缺失的任务类别、完成量与摘要 → 程序核对结构、身份字段、费用与全部代理 → 按授权上传”。难度字段不采集、不计算、不参与排名分组。字段齐备时可由程序直接渲染固定摘要；这不等于程序能理解任意旧对话。让模型在任务结束时顺带生成结构字段，也会产生当次输出 Token，只是减少另一次整段历史重读。

宿主的 AI heartbeat 每次唤醒也可能产生模型调用，即使随后发现没有新数据。只有宿主支持先由程序检查再唤醒模型时，才能避免这种空跑；没有该能力时如实告知，不能把“没有读取正文”说成“没有模型费用”。独立 monitor 没有这个模型唤醒成本，但也不会自行完成缺失的语义整理。

将整理本身登记在 envelope.collectionProcessing：同一次运行用稳定 runId，记录 method、inputBasis、新分类/复用记录数、模型及 Harness、调用次数、全部整理子代理、Token、已知实付、币种及 costRelation。init 已生成此字段模板。计量尚未返回时填 null/unknown，不能声称零费用；数据下一次取得后保留追补依据。included_in_period 表示已含在账期净实付，禁止再次加总；outside_period 作为采集开销单列，不算额外成功根任务。不要把“整理上一轮采集记录”再次当作业务工作，不递归总结监控日志。

## 成功位置与重试

所有命令使用同一个绝对 `--state` 路径和 `--identity` 路径。本地状态默认 `.local/collection-state.json`，含选择、目标站点、成功采集终点和未完成批次；不上传状态文件。更换身份或站点后重新选择范围。

每次 init 固定 `[startAt, endAt)`。不要在整理结束时改写 endAt，否则整理期间新产生的记录会被错误跳过。失败重试使用原 capture、record、preview 和幂等键。只有服务器返回与当前内容摘要一致的已保存回执，才推进本地成功位置；preparing、preview、请求发出、超时和失败都不推进。

同一选定区间按真实账期、币种或体积拆为多份时，各份使用同一 `collectionWindow.batch.id`，设置稳定的 `part=1..total`。全部份数成功后才推进。先确定总份数再上传；不能漏掉失败任务、部分代理或后续文件，把 total 改成已成功的份数。超过 512 KiB 不截断字段。状态锁避免并发写入丢失位置；定时与手动采集也应避免重叠运行。

时间窗口只决定采集授权范围，不改变真实账期、账单或任务边界。按调用付费可上传窗口内互不重叠的已知费用片段；对整个订阅账期的实付不能每次重复记入短区间，也不能擅自按天均摊。缺少完整生命周期或账期时标为 partial，仅保留个人观察。跨窗口任务的 UUID 保持稳定；已上传费用不能在后续再次加总。没有新记录不制造零费用任务、不上传空样本；不凭一次空扫描推进“成功上传”位置。

## 按用户选择创建定时运行

CLI 的 preferences 只保存授权策略，**不是操作系统调度器**。需要 AI 提取旧对话时，用户选择开启后使用 Harness 支持的真实调度功能创建，再将返回的 ID 保存到 `preferences --schedule-id <ID>`。不能只写配置就报告“已自动运行”。已有结构字段或额度读取优先使用下面的独立程序，不为了每天上传而再次调用模型。

需要 Codex AI 每天整理历史时使用 `automation_update` 创建当前 chat 的 heartbeat，不用自写 cron 替代该 heartbeat。仅在用户选择自动运行之后创建。首次成功上传是后续工作增量的起点；尚无成功位置时要求用户先选择范围，不能自行选历史。

例：用户已授权每天只生成预览，来源为指定目录时：

```text
npm run contribute -- preferences --incremental on --automation preview --source-scope <授权目录或索引文件> --every-hours 24 --state <绝对状态路径> --identity <绝对凭证路径>
```

自动上传模式还需 `--automation upload --endpoint <已确认站点> --share <已选分享范围>`。调度提示词写清楚这些确定值，不能包含访问密钥。内容应包括：

> 按 OpenCost 贡献 Skill 使用已登记的本地状态、凭证路径、授权来源及分享范围。先执行 init --scheduled，使用新的运行输出目录；失败时不读历史。间隔超过 3 天、授权关闭、来源或凭证变化时停止本次采集，向用户展示首次时间范围选择。检查到未完成批次时保留原预览，按授权重试，不能新建范围跳过它。仅处理明确区间内的真实记录，按全部层级代理汇总，完成本地脱敏及程序校验。预览模式只保存本地预览，提示用户审核；上传模式仅在原授权范围内使用 submit --automatic。后端计算不用大模型。没有新记录或状态未改变时保持安静，只有新待审预览、上传完成、失败、范围需重选或需要用户操作时通知。

自动上传仍需生成完整 preview 并由程序核对内容摘要、时间窗口、凭证、站点、分享范围；`--automatic` 不是绕过这些核对的通用确认。模式为 preview/off 时它会拒绝上传。

用户要求关闭时先 `preferences --automation off`，再用宿主工具暂停对应 scheduleId。关闭增量也停用自动运行。检查实际工具返回后才报告定时任务已关闭；本地自动上传会立即被关闭的偏好阻止。

## 独立后台程序

用户明确选择监控或已有字段每日上传时，读取同一固定版本的 `docs/monitoring.md`。使用 `monitor init/template/schema` 生成字段，按照选定来源填配置。先 `grant --mode local` 或 `grant --mode upload --range <用户选择> --incremental <on/off> --endpoint <目标>` 保存选择，再 `run` 或使用 `scripts/Start-Monitor.ps1` 隐藏运行；仅在用户选择登录启动后使用 Install。后台独立运行，既不依赖本次 Skill 是否还开着，也不调用大模型。不要在本功能开发或演示时擅自为当前用户启用。

后台最多 20 个明确来源，默认 5 分钟、网络串行、8 秒超时、响应上限 1 MiB；文件未改不重新解析，HTTP 使用条件请求，失败退避，已知重置边界适度加采。本地 SQLite 保存完整快照和事件；每天分批上传，内容摘要、幂等键、私人身份和已选范围都要匹配。哈希校验按需进行，不每轮全库重算。工作预览按窗口与批次顺序上传；没有新回执和来源读取失败不推进成功位置。

读 `monitor status` 查看各源上次成功、失败次数、下次检查、重置时间、额度变化、上传成功位置和 attention。间隔超过 3 天的 choose_range 必须向用户展示首次范围选择；非交互后台只暂停补传并保留提示，不假装已经弹窗。用户选择关闭时执行 monitor off/stop，并按其选择移除登录调度。所有历史保留。实际未运行或未验证的系统调度状态如实说明。
