# 可选的结构观察

新增可选 `codeMeasurements`：只能来自用户主动选择、通过固定程序校验的代码/补丁数值报告，不从模型口述、聊天长度或对工作难易的印象生成。默认没有这一字段；`--extended-observations` 也不打开代码采集。完整字段、程序命令和说明见 [代码观察上传](../../../docs/code-observations-upload.md)。

本地用 `attach-code-measurements --input local-capture.json --manifest selected-reports.json --enabled --out NEW-capture.json` 选择报告，再执行capture与prepare。程序保留版本、声明阶段、范围、数值、分布及缺项，剥去代码报告中的本地要求UUID、测量时间和调试读取信息，校验后才生成 `tasks[].observations.codeMeasurements`。源码、原始差异、路径和函数名不上传；不得手工把原报告或绑定清单贴入Envelope。

一个根目标同一测量族/阶段只选一份快照，补丁每阶段一份。要求引用不同、旧观察冲突或超过容量时不采用成功前缀；没有报告就省略字段，不能填零、复制别的任务报告或声明已认证。未测得的报告保留未知，提案不变成已完成，后验代码不进入事前要求判断。新字段只用于本人描述性反馈，不改变验收、费用或公共排名；原有上传预览、确认和自动权限要求继续适用。

这些字段用于描述要求、验收、等待和后续结果，不启用难度分级，不增加任务数，不证明真实性。仅当用户选择扩展记录且已有对应事实时，执行：

```powershell
npm run contribute -- init --out .local/new-capture.json --range 3d --incremental off --automation off --extended-observations
```

时间范围、增量与自动运行参数采用用户实际选择。此处的命令只是关闭自动运行的示例。未带 `--extended-observations` 的模板没有 `task.observations`；带参数也只生成空字段，不读取历史、不调用模型、不授予上传权。已有 capture 可按同一协议选择性添加字段。

## 字段与来源

`task.observations.version = task-observations-1`。原五个部分和新增codeMeasurements均可省略；空模板仍只提供原有四部分，history和代码观察由用户另选本地记录后生成。上传禁止自由文本、业务名称、路径、原文、账号、原文哈希与外部任务 ID：

| 部分         | 可记录内容                                                                                             | 解释边界                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| requirements | 要求是否明确、输入材料状态、现成方案复用程度、知识与推理类型、方法族、约束类别、上下文复用             | 只能提取原要求或已批准变更；这些类别没有难度权重，也不进入排名                           |
| validation   | 计划、已执行、已通过的验收项；关键项；核验独立性；计划制定时点                                         | 区分事前计划与事后补写；没有执行记录不能把“有测试文件”当通过；缺分母不算通过率           |
| followup     | 7 或 30 天观察窗口、实际覆盖天数、重新打开次数、后续缺陷数                                             | 有连续观察来源才能称完整；尚未走完窗口是右删失，无观察为 null，不能说零缺陷              |
| time         | 活跃、等待用户、等待外部、暂停、未知时长；是否互斥                                                     | 并行和重叠时长不相加；只有明确互斥且匹配完整经过时间才计算占比                           |
| history      | 原要求/当前必需项数、当前通过项数、批准变更/待确认提案/重开/验收次数；原要求曾验收、当前核对及重开状态 | 程序从所选本地事件生成，不传事件引用或时间线；没有完整历史不补零，不把多次验收当多个目标 |

每部分都有 `meta`：`source`、`coverage`、`timing`、`missingReason`。按实际来源选择日志、成果解析、用户报告、本地模型、本地规则或未知。来源声明不能升级成独立核验；本地模型提取必须标 `local_model`，不得改成日志或用户确认。

缺项使用 null、unknown 或省略，并填写原因：未记录、不支持、不适用、未授权、来源不可用、已脱敏或未知。`source/coverage` 未知时不能携带已知值。已知为零与未测量不同。完整验收计数须与任务原验收计数一致，关键通过项不超过已执行项。遵守当前 `shared/task-observations.ts` 与机器 schema，不自行添加枚举。

不为填满字段重新扫描全部会话，不把失败、Token 多、耗时长反推成困难，不把代码行、文件数、调用数算成验收目标。程序检查数值边界和一致性；它无法单凭上传 JSON 判断用户最初是否编造。

## 要求历史

仅在已有用户选择的结构事件时，运行 `task-history-analyze --input selected-history.json --out NEW-history-report.json --enabled`。`task-history-template` 只生成明确标识的方法示例，不能当作用户的真实事件。机器 Schema 用 `schema --format task-history` 导出。未启用的分析命令不读取指定源文件；命令只写新文件。

本地协议 `opencost-local-task-history-1` 使用随机根目标及要求引用、明确父事件、发生时间和记录时间。可表达原要求、变更提案、批准/拒绝、同一成果版本的逐项检查、阶段、结束和重开。只按父关系重放；分叉、缺父、冲突、容量超限不生成可上传前缀。模型自报的批准不改变范围，模型自报通过不替代用户或验证器检查；这些来源声明本身也不是身份认证。

给本地 capture 添加 `taskHistory` 后，`capture` 运行同一分析器，并要求事件根目标集合与所选任务完全一致。上传投影只有数量、固定枚举、布尔/未知和来源覆盖；原条件、成果、事件引用及时间线留在本地。程序拒绝与原验收数量、进度、终态和要求锁定相矛盾的投影，不静默修改原任务。局部覆盖只保留本次提供的事件小计，其余总量和状态未知。

原要求曾经验收与当前仍在重开可以同时成立；未结束不算最终失败。缩减条件后的验收只说明当前范围通过。已知范围变化、重开未结束或历史覆盖未知的当前记录及其相交旧结算暂停参与当前比较；私人记录同样生效，但私人任务不进入公开摘要。旧报告按原接收截止保留。

恢复同要求比较需要完整累计费用、当前终态和明确的有效结算修订，不能靠更晚时间或新 UUID 清除另一条未关联的重开记录。跨要求版本结算、多链合并和跨期差额尚未支持。完整协议及边界见 [要求历史](../../../docs/requirement-history.md)。

## 可选本地经济事件核对

用户选择核对跨月退款与要求费用时，可用economic-history-template生成明确标识的方法示例，或对已有用户选择的经济事件JSON运行economic-history-analyze --input selected-ledger.json --out NEW-report.json --enabled。默认关闭，不扫描账单、账号、支付软件、邮箱或其他文件，不调用模型。仅在有记录依据时填写结算状态、金额及任务/要求归属；不得编造经济事件或把供应商请求成功自动当现金到账。

同一收费/退款的多次观察使用本地随机事件引用及单父修订，现金窗口和要求历史覆盖分别说明。程序保留跨月现金、归回原要求的费用、分配未知时的可行范围及缺项；赠额不作现金退款。分析结果含准确金额、时间和本地引用，只供本地查看，不得塞入Envelope、capture、普通摘要或自动上传。它不会修改已有结算、费用或排名。详见[本地经济事件](../../../docs/economic-history.md)。

## 预览与反馈

生成的新字段随正常 `capture → prepare → 确认 → submit` 流程展示。只上传 envelope，不上传 capture、来源材料或本地树。已有用户授权范围不自动扩大；默认不开扩展采集，自动运行沿用单独授权。

反馈的 `analytics` 是本次记录的描述统计，每项带已知观察数、应观察数、分母与解释。`comparisonCoverage` 说明多少根目标可与社区比较及未比较原因；最多展示 24 组工作条件，未评估的剩余目标单列，不代表未匹配。

推荐展示历史月份、模型、Harness、候选数、费用口径和来源分布。来源数不等于独立人数；来源间范围与四分位不是置信区间。非验收状态的已花费用不能统称浪费。无充分样本时仍可展示本人统计，不补写用户名次、节约承诺或最佳套餐。

公开锚点的 Rasch 校准仅供本地研究，需单独 `calibrate-difficulty --enabled`，不由日常 Skill 自动执行、不随摘要上传、不进入生产排名。算法和来源见 [分析方法](../../../docs/analysis-methodology.md)。
